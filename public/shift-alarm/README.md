# 班表闹钟

把 iPhone 自己设不出来的上班规则，算成一张能逐天核对的班表，再导进 iOS 日历。

线上：`/shift-alarm/`（规范入口 `/patterns/apple-shift-alarm/pattern.html`）

---

## 它解决的是什么

iPhone 的时钟闹钟只有一种重复方式：**每周固定星期几**。而国内一大批人的班根本不长这样：

| 班型 | 时钟闹钟能不能设 |
| --- | --- |
| 大小周（隔周多上一个周六） | ✗ 没有「隔周」这个选项 |
| 调休补班（某些周六周日反而要上班） | ✗ 而且每年日期都不一样 |
| 法定放假（放假的周一别响） | ✗ 只能手动关了再记得开回来 |
| 做四休三 / 上四休二（滚动循环） | ✗ 循环长度和 7 天的星期对不齐 |
| 两班倒 / 三班倒 / 四班三倒 | ✗ 起床时间每天都在变 |

Siri 和系统自带的智能同样设不出来——这不是「问法不对」，是闹钟的数据模型里就没有这些概念。
于是每年都有人在补班的周日睡过头，在放假的周一被叫醒。

## 怎么做的

```
一句话班规
   ↓  parser.js       本地确定性解析（不联网、不要 key），拿不准的一律抛出来问
规则对象 (JSON)
   ↓  engine.js       逐天展开成确定班表，五层依次覆盖，每层都留 trace
班表 + 提醒实例
   ↓  ics.js          编译成 iOS 日历直接认的 .ics
一条链接 → 分享面板 → 日历
```

五层覆盖的顺序是显式的，也是界面上点开某一天能看到的解释：

1. **班型** —— 固定周 / 大小周 / 滚动循环
2. **法定放假** —— 放假日不上班
3. **调休补班** —— 被挪成工作日的周末要上班（能把「小周的周六」也翻成上班）
4. **请假** —— 整段变休
5. **手动覆盖** —— 你说了算，压过上面所有层

## 目录

| 文件 | 作用 |
| --- | --- |
| `engine.js` | 规则引擎。纯函数、零依赖，浏览器与 node 通用 |
| `ics.js` | iCalendar 导出（RFC 5545） |
| `parser.js` | 中文班规解析 + 模型提示词 + 模型输出收编 |
| `holidays-data.js` | 国务院办公厅历年放假与调休安排 |
| `pattern.html/.css/.js` | 界面（iOS 分组列表风格，加到主屏可当 app 用） |
| `pattern.json` | 契约：模块、关键设计决策与它们各自防的是哪个坑 |
| `tests/` | 单元测试 + 跨实现复核 |

三个逻辑模块都是零依赖 ES module，可以单独拿去用：

```js
import { expandSchedule, expandReminders } from './engine.js';
import { buildICS } from './ics.js';
```

## 跑测试

```bash
public/shift-alarm/tests/run.sh
```

两部分：

- **63 条单元测试**（引擎 22 / 导出 20 / 解析 21）
- **135 项跨实现复核** —— 用 **python 的 icalendar + dateutil.rrule** 把我们生成的 `.ics`
  重新解析、重新展开重复规则，逐条比对是否与引擎算出的提醒实例集合**完全相等**。
  自己写的 `.ics` 用自己写的解析器去验等于没验，所以这一步换了实现。
  （需要 `pip install icalendar python-dateutil`。）

## 几个不显然的决定

完整清单在 `pattern.json` 的 `designDecisions` 里，每条都写了它防的是哪个坑。挑三条最要命的：

**绝不生成 `RDATE`。** Apple 日历不支持它——事件能导入，但重复被静默丢弃、只在第一天出现。
调休补班日一律写成带独立 UID 的单条 `VEVENT`。这类错误没有任何报错，
症状是补班那天早上一声不吭。

**`INTERVAL=2` 只配单个 `BYDAY`。** `FREQ=WEEKLY;INTERVAL=2;BYDAY=SA,SU` 在 `WKST=SU` 下
会把周六周日判进相邻的两个双周，而 Apple 的 EventKit 倾向于自己写 `WKST=SU`。
大周同时上周六周日的人会因此每隔一周被叫错一天。遇到就拆成两条。

**重复规则是从日期集合反推出来的，而且构造完还要再自检一遍。**
`展开(RRULE) − EXDATE + 例外单条 ≡ 引擎算出的集合`，不等就整组退回逐日展开，
并把这件事写进界面上的 warnings。宁可多几条事件，也不发一份可能少响一天的日历。

## 三条导入路径

| 路径 | 怎么走 | 什么时候用 |
| --- | --- | --- |
| **分享面板**（默认） | `navigator.share({files})` → 选「日历」 | 最省事，一次性导入 |
| **下载 .ics** | blob → 文件 App → 点开 | 分享面板不可用时的兜底 |
| **webcal:// 订阅** | 把 .ics 放到任意公开 https 地址，点 webcal 链接 | 想让班表**自动同步**、以后一键整体删掉 |

webcal 是 iOS 上最短的一条：点一下直接弹出「订阅日历」，不经过文件 App、
不产生下载，加到主屏当 app 用时也照样能点动（`<a download>` 在那个模式下普遍失效）。
代价是需要一个公开地址——本工具全部在本机算、没有服务器，得你自己把文件放上去。

订阅有两个开关会**悄悄**把提醒吞掉，页面上也写了：订阅表单里的「移除提醒」要保持关闭，
订阅后在日历里确认这个日历的「事件提醒」是开着的。否则日历照常显示，但一声都不会响。

## 说清楚做不到的

- **日历提醒不是闹钟。** 它是普通通知，会被静音开关、专注模式、定时推送摘要压掉，
  不像时钟 App 的闹钟能盖过铃声开关。想真被叫醒，要么在专注模式里放行日历，
  要么按页面上那段配方用快捷指令去控制真正的闹钟。这一点在界面上是写在最显眼处的。
- **不提供现成的快捷指令文件。** iOS 15 起快捷指令的正常导入路径要求文件经 Apple
  签名（AEA），而签名只能在 Apple 自己的设备上完成，静态页面做不到。未签名的 plist
  在某些设置下是否还进得去，各方说法并不一致，而这件事没法在没有真机的情况下拍板——
  所以不押它，给的是「在手机上建一次」的分步配方 + 可复制的班表数据。
  建好之后可以「分享 → 存储为文件 → 任何人」导出一份**已签名**的，换机直接导入。
- **个人自动化不能被分享或导入**，每天定时运行那一步只能自己建。
- **法定节假日只到数据文件里已有的年份**（新一年通常在前一年 11 月前后公布）。
  没收录的年份只按班型推算，界面会明确警告，不会假装算得准。
