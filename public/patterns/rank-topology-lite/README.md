# 模型分片与训练设备映射 · 简洁版 · Pattern

> 构建产物：`/patterns/rank-topology-lite/pattern.html`
> 中央矩阵本体：[`/patterns/rank-topology-3d/`](../rank-topology-3d/pattern.html)（同源 iframe 嵌入，不是拷贝）
> 契约：同级 `pattern.json`

## 它是什么

`/patterns/rank-topology-3d/` 的**简洁版**——但「简洁」落在外层，不落在矩阵本身，也不落在
「把矩阵缩小塞进一张卡片」这件事上。

矩阵、排布、六档通信、preset、ZeRO、物理平铺、它自己的拖动/缩放镜头，这一份**不改它的功能/外观**：
中央就是 `/patterns/rank-topology-3d/pattern.html` 本体，同源 iframe，**铺满整个视口、边到边**，
不加框、不加标题条、不缩小。默认把它定在盘古 ProMoE 预置（`theme=dark`）：
`world = TP8 × PP5 × DP100 = 4000` 卡全量渲染，`EP2` 是同一批 rank 内部的专家路由维度，不额外乘进
rank 总数。它本来的密度就是它的样子——接受它，不裁剪它。

唯一一处例外是性能：这一份给 iframe 多传了一个 `fastcard=1`——矩阵共用的 `demo.html` 里新增的
一个**默认关闭**的可选参数，静置态（没有任何选中）把 4000 只素壳的棱/面从「每只卡各自十几个
DOM 节点」合批成按深度分桶的几百个 `<path>`，颜色/位置逐像素不变，只是节点数从约 10.7 万降到
约 3.6 万；一旦点开一张卡它就自动让位回原来逐卡画法。这个参数默认不传，`rank-topology-3d` 直接
打开不受影响——只有这个简洁版会传它。

**拓扑本身就是全屏幕的无限画布**——不是另包一层镜头、把矩阵缩成中间的一张卡片（像 Miro：
画布上的内容本身就是画布，不是画布里又嵌一张缩小的画布）。矩阵自己的拖动、缩放、选组、悬停读数，
原样在场，这一层不叠加第二套镜头逻辑。

点一张卡下钻之后（矩阵页自己上报的 `pto:select`，不是这一层另算的），一张卫星卡浮出来，贴在屏幕
右边——像便签一样浮在主画布上层，不占用、不缩小主画布本身。卫星卡走
[compute-graph-viewer 的抽象图网页 prompt](https://github.com/yinyucheng0601/compute-graph-viewer/blob/main/docs/抽象图网页prompt.md)
（深色极简、无边框灰卡、语义配色只落在训练语义图元上）——这份 prompt 管的是卫星卡，不管矩阵内部
怎么画。**卫星卡不放文字标签**：卡上只留 rank 号（认卡、点了能收起）和一条执行活动色条，没有坐标
行、没有色块逐个的提示文字，靠颜色本身说话；真实坐标这些数值仍然要看，就回矩阵本体里选中同一张
卡，读出面板都在那边，卫星卡不重复画一遍。

## 结构

- **中央矩阵**：`<iframe>` 铺满整个视口（`position:fixed; inset:0`），指向
  `../rank-topology-3d/pattern.html?embed=1&theme=dark&preset=pangu&...`。它自己的六档通信切换、
  preset 切换、ZeRO 档位、物理平铺、拖动缩放镜头、悬停读数——全部照常可用，这一层什么都没削减、
  没有额外的边框或镜头包着它。
- **卫星卡**：在矩阵内点一张卡（触发它自己的 `pto:select` 上报）之后，屏幕右边固定叠一层贴出
  一张卡片，只写这张卡的 rank 号，和一段「执行活动」示意色条（前向 → 通信 → 反向 → 通信 →
  优化器，长度示意、非实测——这句话没删，挪进了色条自己的 `title`，只在悬停时才弹出来，默认不占
  地方）。不放坐标行、不给每一小块色块单独挂提示文字——真实坐标、六档通信这些数值型信息，回矩阵
  本体里选中同一张卡看，卫星卡不重复画一遍。点卡片右上角的 `×` 收起。卫星卡贴在视口上，不跟随
  矩阵自己的镜头缩放/平移。
- **完整独立页链接**：屏幕下方正中一个极小的角标，点开是不带这一层卫星卡功能的
  `/patterns/rank-topology-3d/` 原页——放在下边正中是因为矩阵自己的标题/设置按钮占了左上右上，
  群组控件占了左下，这是唯一空的一角。

## URL 参数

| 参数 | 取值 | 作用 |
|---|---|---|
| `sel` | 逗号分隔的 rank 列表，如 `12,45,90` | 打开时直接摆好对应的卫星卡；卫星卡不带坐标，纯按 rank 号摆 |

## 数据来源与口径

- 卫星卡的下钻信号来自矩阵页自己通过 `postMessage` 上报的 `pto:select` 事件里的 `sel`（真实被选中的
  rank 号），这一层不重新推导、不再解读其余字段——卫星卡本身不显示坐标，也就不需要矩阵页上报的
  `groups`。真实坐标（`TP/CP/PP/DP/EP`）想看，回矩阵本体里选中同一张卡，它自己的读出面板有。
- `world = TP8 × PP5 × DP100 = 4000`：盘古 ProMoE 预置的口径，来自矩阵页实际上报的 `config` 字段，
  不是按「EP 也是并行维、理应相乘」的直觉猜的——EP 描述的是同一批 rank 内部路由去哪几个专家
  （All-to-All），不是另开一批副本卡，所以不参与 rank 计数。这一层只用它来校验 `sel` 的取值范围
  （`0 ≤ sel < 4000`），不用来算坐标。

## 它不回答什么

- **完整的并行度组合切换**——preset / 自定义 tp·cp·pp·dp·ep、ZeRO 档位、物理平铺全部还在矩阵本体
  里，只是这一份把默认值定死在盘古预置。想换配置，直接在中央矩阵内部操作（它自己的控制面板都在）。
- **真实计时**——卫星卡上「执行活动」色块的长度没有真实耗时依据，标注「示意，非实测」；真正的耗时
  估算与传输时间下界仍在矩阵本体的读出面板里。

## 依赖

不是自包含：依赖同一个站点上 `/patterns/rank-topology-3d/pattern.html` 一起发布。离线打开这一份
文件、或者那条路径不存在时，中央矩阵会是一格空白 iframe——这是有意的取舍：打包一份拷贝会让两份
实现分叉，`demo.html` 的修复不会自动传到这一份。
