# 模型分片与训练设备映射 · 简洁版 · Pattern

> 构建产物：`/patterns/rank-topology-lite/pattern.html`
> 两个本体：[`/rubik-pattern.html`](../../rubik-pattern.html)（逻辑魔方）+
> [`/patterns/rank-topology-3d/`](../rank-topology-3d/pattern.html)（并行拓扑矩阵）——
> 都是同源 iframe 嵌入，不是拷贝
> 契约：同级 `pattern.json`

## 它是什么

`/patterns/rank-topology-3d/` 的**简洁版**——但这一版的「简洁」不是靠改矩阵本身、也不是靠加一层
弱化渲染凑出来的：未点开任何一张卡时，铺满整个视口的是**逻辑魔方**（`/rubik-pattern.html`，
WebGL 实例化网格，盘古 ProMoE 预置 4000 卡全量渲染）——它本来就是素块、没有文字标签、没有显示
密度问题、也没有性能问题，这正是「点开之前」想要的默认视图，不必在 SVG 矩阵里再拼一套。

点开一张方块之后，**留在逻辑魔方自己身上**——它自带的选中态渲染（这张卡的四维身份、结构、
"卡内魔方"局部聚焦）已经是干净的效果，不必换到矩阵那一屏再画一遍。宿主在角落浮出一句"↓ 单卡
下钻"邀请，点了才真正换到**并行拓扑矩阵本体**（`/patterns/rank-topology-3d/pattern.html`），
带上那张卡的 `?sel=&solo=1`——这时才是矩阵的强项：真实容量读出、显存构成明细、卡内那一级通信。
见下面「三档取景」。

两个本体都不改功能、不改外观，各自负责它本来就做得最好的那一半：逻辑魔方负责「阵列有多密、排成
什么形状」以及「选中这一张之后它在阵列里的局部上下文」，并行拓扑矩阵只负责「真要下钻时的全部
数字细节」。**拓扑本身就是全屏幕的无限画布**——不是另包一层镜头、把矩阵缩成中间的一张卡片；
两个 iframe 都铺满整个视口，边到边，不加框、不缩小。

**规模小的时候，无限画布本身就是多余的一层**——`world`（`tp×pp×dp`）≤ 64 时，这一份直接铺满
并行拓扑矩阵本体的原页，不铺逻辑魔方、不裁剪它的任何交互，跟直接打开 `/patterns/rank-topology-3d/`
逐字节相同。64 张卡的 SVG 阵列本来就没有密度/性能问题，逻辑魔方"先看形状"的价值这时反而是
多绕一圈——见下面「URL 参数」的 `preset`。

## 三档取景

「无限画布」是三个真实档位，越往里画得越少、看得越细：

1. **集群**——逻辑魔方铺满，没有选中任何卡。
2. **选中**——点一张魔方方块之后，**留在逻辑魔方身上**：它自己的选中态渲染（局部聚焦、四维
   身份、"卡内魔方"）原样接管，这一层不换 iframe、不重画一遍。宿主右上角浮出一句极简的
   "↓ 单卡下钻"邀请（rank 号 + 坐标 + 层段，来自逻辑魔方自己 `onSelect` 报的数），不摆容量/
   显存数字——矩阵没打开，那些数字这一刻并不存在，编不出来。
3. **单卡下钻**——点那句邀请，才真正换到并行拓扑矩阵本体，带 `fastcard=1&solo=1`：连兄弟卡
   也隐去，看的是这一张卡内部的填充版——真实容量读出、显存构成明细（保留矩阵原本的彩色：
   权重/梯度/优化器态/专家/激活各自的颜色在说"这一块字节是什么"，不是装饰；这一档只服务
   一张卡，不会跟别的卡的颜色打架，彩色比黑白更好读）、卡内那一级通信。宿主右上角这时才
   浮出真数据卡，内容是矩阵上报的、已经算好的摘要（坐标、层段、容量告警、显存构成）——这
   一层自己不重算、不编数字，读出面板与浮卡永远是同一套数。

退档跟"点空白处"同一条规矩：返回按钮**一次退一档**，不直接甩回最外层。第 3→2 档不换 iframe，
只让矩阵切自己的 `soloCard`（一句 `pto:tier` 指令）；第 2→1 档才真的把矩阵藏起来，回到逻辑
魔方——它本来就还停在原地，不用重新加载。tier2 完全不涉及 iframe 切换，天然没有闪烁，这也是
"切换要丝滑"这条要求最终落地的方式：不是靠更长的过渡动画补出来的，是靠少切一次省出来的。

## 结构

- **逻辑魔方（默认层 + 第二档）**：`<iframe>` 指向
  `../../rubik-pattern.html?theme=dark&tp=8&pp=5&dp=100&ep=2&color=neutral&groupgap=3`
  （默认盘古 ProMoE 预置，与矩阵本体的 `world=4000` 口径一致），铺满整个视口。`color=neutral` 与
  `groupgap=3` 是这个简洁版才传的两个参数：前者默认素色（先看阵列形状，不看负载热力），后者
  拉开 tp/pp/dp/ep 各组之间的缝，让分组更明显——独立打开 `/rubik-pattern.html` 默认值不变。
  它自己的旋转/缩放镜头、形态切换（标准/DP/EP/TP/PP/物理）、着色镜头、时间轴、选中态渲染——
  全部照常可用，这一层不裁剪它的任何功能，选中之后也不会被换掉。
- **并行拓扑矩阵（第三档，只在点了"下钻"之后才加载）**：把逻辑魔方报的 `(tp, pp, rep)` 坐标
  换算成矩阵本体自己的 `rank` 编号（见下方「两套 rank 编号」），矩阵 iframe
  （`../rank-topology-3d/pattern.html?embed=1&theme=dark&preset=pangu&fastcard=1&solo=1&sel=...`）
  这时才第一次加载。矩阵自己的读出面板、六档通信、拖动缩放镜头、显存构成的原色——全部照常
  可用；`fastcard=1` 做几件收敛：选中之后不画坐标轴刻度/EP 组框、选中即刻飞焦到那张卡、取消
  选中飞回默认机位。`solo=1` 连兄弟卡也隐去，只看这一张卡内部——矩阵现在只在第三档才被打开，
  打开就直接是这一档。不传 `mono`：第一/二档的素色是给"阵列有多密"这类形状问题用的，第三档
  问的是"这一张卡里装了什么"，颜色这时是信息不是装饰，所以保留原色。`rank-topology-3d` 直接
  打开不传这两个参数，外观和交互一个字节不变。
- **返回按钮**：第二档起左上角出现，文案跟着当前档位换——第三档是「← 返回选中+兄弟」，第二档
  是「← 返回魔方视图」；点回去第 3→2 档不重新加载矩阵（只让它切一档），第 2→1 档才真的把矩阵
  藏起来，逻辑魔方保留原地的镜头位置，随时可以再点别的方块。
- **完整独立页链接**：屏幕下方正中一个极小的角标，点开是矩阵本体的原页
  `/patterns/rank-topology-3d/`——放在下边正中是因为两个本体各自的标题/设置按钮都占了上半区，
  这是唯一稳定空着的一角。

## 两套 rank 编号：为什么点选要换算，不能直接传数字

逻辑魔方与并行拓扑矩阵各自独立实现了一遍「rank ↔ (tp, pp, dp) 坐标」的换算，内部打包顺序不一样：

| | 打包公式（cp 固定为 0，未入式） |
|---|---|
| 逻辑魔方 `pattern.js` | `rank = (rep × PP + pp) × TP + tp` |
| 并行拓扑 `demo.html` | `rank = (pp × DP + dp) × TP + tp` |

两边都用 `tp` 当最内层（`% TP` 同一个数），但 `pp` 与 `dp`/`rep` 的打包顺序不同——同一个数字在
两个系统里指的不是同一张卡，必须按坐标三元组换算，不能把 `rank` 数字直接抄过去。
`pattern.js` 里的 `rubikSelToMatrixSel()` 做的正是这件事：拿逻辑魔方 `onSelect` 回调给出的
`{tp, pp, rep}`，按矩阵本体自己的公式重新打包成它的 `sel`。

**已验证**：逻辑魔方 rank 830（`tp=6, pp=3, rep=20`）换算得到矩阵 rank 2566；用
`?sel=2566` 直接打开矩阵本体，它读出的坐标正是 `tp6 · cp0 · dp20 · pp3`，与逻辑魔方报的坐标
逐位一致。

## URL 参数

| 参数 | 取值 | 作用 |
|---|---|---|
| `sel` | 并行拓扑矩阵自己的 rank 编号，如 `2566` | 打开时直接进入第三档，显示这张卡的填充版详情——用的是矩阵本体自己的编号，不是逻辑魔方的编号（深链场景不经过逻辑魔方，没有换算的必要，也没法换回第二档——退回来会直接落到集群那一档） |
| `preset` | `pangu`（默认，`tp8·pp5·dp100·ep2`，world=4000）\| `dense64`（`tp4·pp4·dp4·ep1`，world=64） | 选 `world ≤ 64` 的预置时，直接跳过逻辑魔方与三档取景，铺满矩阵本体的原页——验证的正是"规模小时无限画布本身是多余一层"这条规则确实会触发，不是摆着不用的死分支 |

## 它不回答什么

- **完整的并行度组合切换**——两个本体各自的 preset / 自定义 tp·cp·pp·dp·ep、ZeRO 档位、物理平铺
  都还在，只是这一份把默认值定死在盘古预置。想换配置，直接在对应的本体内部操作。
- **逻辑魔方与矩阵本体之外的第三套渲染**——这一层只做「选谁、换算成谁的编号、切哪个 iframe 在
  上层」，不重新画卡、不重新算内存/容量，那些都是两个本体各自的职责。

## 依赖

不是自包含：依赖同一个站点上 `/rubik-pattern.html` 和 `/patterns/rank-topology-3d/pattern.html`
一起发布。离线打开这一份文件、或站点没有那两条路径时，对应的 iframe 会是一格空白——这是有意的
取舍：打包拷贝会让实现分叉，两个本体各自的修复不会自动传到这一份。
