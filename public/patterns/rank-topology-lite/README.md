# 模型分片与训练设备映射 · 简洁版 · Pattern

> 构建产物：`/patterns/rank-topology-lite/pattern.html`
> 两个本体：[`/rubik-pattern.html`](../../rubik-pattern.html)（逻辑魔方）+
> [`/patterns/rank-topology-3d/`](../rank-topology-3d/pattern.html)（并行拓扑矩阵）——
> 都是同源 iframe 嵌入，不是拷贝
> 契约：同级 `pattern.json`

## 它是什么

`/patterns/rank-topology-3d/` 的**简洁版**——但这一版的「简洁」不是靠改矩阵本身、也不是靠加一层
弱化渲染凑出来的：未点开任何一张卡时，铺满整个视口的是**逻辑魔方**（`/rubik-pattern.html`，
WebGL 实例化网格，盘古 ProMoE 预置 4000 卡全量渲染）——它本来就是素块、没有文字标签、没有显示
密度问题、也没有性能问题，这正是「点开之前」想要的默认视图，不必在 SVG 矩阵里再拼一套。

点开一张卡之后，画面换成**并行拓扑矩阵本体**（`/patterns/rank-topology-3d/pattern.html`），带上
那张卡的 `?sel=`——真实坐标、内存/容量读出、六档通信、兄弟卡高亮，矩阵自己的选中态渲染原样接管，
这一层不重新画一遍。

两个本体都不改功能、不改外观，各自负责它本来就做得最好的那一半：逻辑魔方负责「阵列有多密、排成
什么形状」的静态全貌，并行拓扑矩阵负责「点开这一张卡之后要看的所有细节」。**拓扑本身就是全屏幕
的无限画布**——不是另包一层镜头、把矩阵缩成中间的一张卡片；两个 iframe 都铺满整个视口，边到边，
不加框、不缩小。

## 结构

- **逻辑魔方（默认层）**：`<iframe>` 指向 `../../rubik-pattern.html?theme=dark&tp=8&pp=5&dp=100&ep=2`
  （盘古 ProMoE 预置，与矩阵本体的 `world=4000` 口径一致），铺满整个视口。它自己的旋转/缩放镜头、
  形态切换（标准/DP/EP/TP/PP/物理）、着色镜头、时间轴——全部照常可用，这一层不裁剪它的任何功能。
- **并行拓扑矩阵（详情层）**：点一张魔方方块（触发它自己的 `rubik-select` 上报）之后，这一层把
  逻辑魔方报的 `(tp, pp, rep)` 坐标换算成矩阵本体自己的 `rank` 编号（见下方「两套 rank 编号」），
  把矩阵 iframe（`../rank-topology-3d/pattern.html?embed=1&theme=dark&preset=pangu&card=1&fastcard=1&sel=...`）
  切到最上层。矩阵自己的读出面板、六档通信、兄弟卡高亮、拖动缩放镜头——全部照常可用；`fastcard=1`
  （矩阵共用的 `demo.html` 里默认关闭的可选参数）额外做四件事，都是这个简洁版才要的收敛：选中
  之后不画坐标轴刻度/EP 组框（不需要再读一遍"这是第几组"，读出面板已经写了真实坐标）；跟选中的
  卡毫无关联的卡直接不画（不是淡出，是真的不画，兄弟卡照常有内容）；选中即刻飞焦到那张卡；取消
  选中（点画布空白——矩阵本体自己早就支持这个手势）飞回默认机位。`rank-topology-3d` 直接打开不
  传这个参数，外观和交互一个字节不变。
- **返回按钮**：详情层左上角「← 返回魔方视图」，点回去不销毁两个 iframe（只是换哪个在最上层
  显示），逻辑魔方保留上次的镜头位置，随时可以再点别的方块。
- **完整独立页链接**：屏幕下方正中一个极小的角标，点开是矩阵本体的原页
  `/patterns/rank-topology-3d/`——放在下边正中是因为两个本体各自的标题/设置按钮都占了上半区，
  这是唯一稳定空着的一角。

## 两套 rank 编号：为什么点选要换算，不能直接传数字

逻辑魔方与并行拓扑矩阵各自独立实现了一遍「rank ↔ (tp, pp, dp) 坐标」的换算，内部打包顺序不一样：

| | 打包公式（cp 固定为 0，未入式） |
|---|---|
| 逻辑魔方 `pattern.js` | `rank = (rep × PP + pp) × TP + tp` |
| 并行拓扑 `demo.html` | `rank = (pp × DP + dp) × TP + tp` |

两边都用 `tp` 当最内层（`% TP` 同一个数），但 `pp` 与 `dp`/`rep` 的打包顺序不同——同一个数字在
两个系统里指的不是同一张卡，必须按坐标三元组换算，不能把 `rank` 数字直接抄过去。
`pattern.js` 里的 `rubikSelToMatrixSel()` 做的正是这件事：拿逻辑魔方 `onSelect` 回调给出的
`{tp, pp, rep}`，按矩阵本体自己的公式重新打包成它的 `sel`。

**已验证**：逻辑魔方 rank 830（`tp=6, pp=3, rep=20`）换算得到矩阵 rank 2566；用
`?sel=2566` 直接打开矩阵本体，它读出的坐标正是 `tp6 · cp0 · dp20 · pp3`，与逻辑魔方报的坐标
逐位一致。

## URL 参数

| 参数 | 取值 | 作用 |
|---|---|---|
| `sel` | 并行拓扑矩阵自己的 rank 编号（`0`–`3999`），如 `2566` | 打开时直接进入详情层，显示这张卡——用的是矩阵本体自己的编号，不是逻辑魔方的编号（深链场景下不经过逻辑魔方，没有换算的必要） |

## 它不回答什么

- **完整的并行度组合切换**——两个本体各自的 preset / 自定义 tp·cp·pp·dp·ep、ZeRO 档位、物理平铺
  都还在，只是这一份把默认值定死在盘古预置。想换配置，直接在对应的本体内部操作。
- **逻辑魔方与矩阵本体之外的第三套渲染**——这一层只做「选谁、换算成谁的编号、切哪个 iframe 在
  上层」，不重新画卡、不重新算内存/容量，那些都是两个本体各自的职责。

## 依赖

不是自包含：依赖同一个站点上 `/rubik-pattern.html` 和 `/patterns/rank-topology-3d/pattern.html`
一起发布。离线打开这一份文件、或站点没有那两条路径时，对应的 iframe 会是一格空白——这是有意的
取舍：打包拷贝会让实现分叉，两个本体各自的修复不会自动传到这一份。
