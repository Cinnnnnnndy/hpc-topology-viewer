# 模型分片与训练设备映射 · 简洁版 · Pattern

> 构建产物：`/patterns/rank-topology-lite/pattern.html`
> 完整交互版：[`/patterns/rank-topology-3d/`](../rank-topology-3d/pattern.html)（六档通信、preset/ZeRO/物理平铺、十层可观测性）
> 契约：同级 `pattern.json`

## 它是什么

`/patterns/rank-topology-3d/` 的**简洁版**。同一个题面——「五刀切完之后，这一份落到哪张卡上」——
保留同一个核心比喻：**world 张卡壳排成的立体阵列**。而且是**全量**：

- 世界大小按**盘古 ProMoE 的公开并行度口径**取 `TP8 × PP5 × DP50 × EP2 = 4000`，
  4000 张卡真的都在场，不折叠、不降级；
- 每张卡都是一个**会被光照出明暗的立方体**（`THREE.BoxGeometry` + `InstancedMesh`），
  不是拿平面卡片摆位置充数——这是「立体显示」这件事本身，不是可选的视觉效果；
- 4000 个会转动的立体实例，纯 CSS/DOM 撑不住这个规模，所以引擎是真的 **WebGL（three.js）**，
  不是上一版尝试过的纯 CSS 3D transform。

「简化」落在别处：去掉六档通信切换、preset 切换、ZeRO 档位、物理平铺这些控制面板，
只留「转一转、点一张卡（或输入 rank 跳转）」。

选中一张卡之后，详情区换成
[compute-graph-viewer 的抽象图网页 prompt](https://github.com/yinyucheng0601/compute-graph-viewer/blob/main/docs/抽象图网页prompt.md)
的画法（深色极简、无边框灰卡、语义配色只落在训练语义图元上、直角连线、不搭装饰性中间层）——
这一份只用在详情区，3D 卡阵本身仍然是立方体 + 空间位置，不是这份 prompt 描述的平面关系图。

## 结构

- **3D 卡阵**（上半屏）：4000 张卡按 `(TP, PP, DP, EP)` 摆成一个可转动的立体阵列。默认静置时
  缓慢自转；拖动可以任意角度查看；拖一下或选中一张卡之后自转停住，方便看清当前选的是哪张。
  - **位置只是直觉示意**：4 个并行维只有 3 根空间轴可用，且 `DP=50` 比其余几维大得多——直接
    拿一根轴装会拉成一条很长的条，所以把 `DP` 拆成 `10×5` 两段分别并进深度轴与纵向轴，换来一个
    接近立方体的外形。选中之后的**真实**坐标只看下方标题文字，不是看它在阵列里的位置。
  - **精确点选**用下方的「跳转到 Rank」输入框（`0`–`3999`，Enter 跳转），不是逐张点选——4000 张
    卡里的大多数都被压在实心阵列内部，从外部点不到；直接点卡阵表面也能选中点到的那张，但选不
    到的更多，跳转框是唯一保证能选到任意一张的方式。
  - 选中标记是一个关闭了深度测试的白色描边立方体，会穿透前排的卡持续可见——否则选中一张压在
    阵列内部的卡时，标记会被前排完全挡住，什么都看不见。
- **Rank 详情**（下半屏）：选中一张卡之后，用「执行活动」与「激活驻留」两组共同标题
  直接连接各自的内容卡片（抽象图 prompt 原句给的例子）：
  - **执行活动**——前向（蓝）→ 通信（绿）→ 反向（粉）→ 通信（绿）→ 优化器（橙）五个色块，
    宽度只表达相对占比，没有真实计时依据，标题下方写明「长度示意 · 非实测」。
  - **激活驻留**——低透明度紫色长条，两端菱形端点：亮紫 `#A856F7` 是驻留产生、
    黄绿 `#88C911` 是释放，边界描边是这张图里唯一保留的描边（因为轮廓本身表达驻留区间的语义）。

## URL 参数

| 参数 | 取值 | 作用 |
|---|---|---|
| `rank` | `0`–`3999` | 初始选中哪张卡（TP8×PP5×DP50×EP2 的 global rank）；不给或非法值退回 `0`，不报错 |
| `embed` | `1` | 嵌入形态：收起顶栏（标题 / Run 信息 / 完整版链接）与页脚（图例 / 状态行） |

## 颜色语义（沿用 `/patterns/rank-topology-3d/` 的映射，不为视觉均衡换色）

3D 卡阵本身保持中性灰——rank 身份是结构性的，不是训练语义，不套用下面这套配色；
配色只用在选中后的详情区：

| 语义 | 颜色 |
|---|---|
| 前向 | `#4469EF` |
| 反向 | `#FF4C7C` |
| 通信 | `#05D793` |
| 优化器 | `#FFAA3B` |
| 激活驻留 | `#8E4ACE`（低透明度长条） |
| 驻留产生端点 | `#A856F7` |
| 释放端点 | `#88C911` |

## 它不回答什么

- **完整的并行度组合**（preset / 自定义 tp·cp·pp·dp·ep、ZeRO 档位、物理平铺）——那是
  `/patterns/rank-topology-3d/` 的题面，这一份固定死盘古 ProMoE 预置 TP8×PP5×DP50×EP2。
- **六档通信切换**（谁和谁 / 搬的是什么 / token 去哪 / 何时 / 代价 / rank 内）——简洁版只画一次
  执行活动的示意色块，不做逐层切换。
- **精确坐标读图**——卡阵里的空间位置是直觉示意（DP 被拆成两段揉进了另外两根轴），不是可以
  直接读出 (TP,PP,DP,EP) 的坐标图；真实坐标只在选中之后的标题文字里。
- **真实计时**——执行活动块的宽度与激活驻留条的长度都没有真实耗时依据，页面上一律标
  「示意 / 非实测」；真正按字节算出的传输时间下界在 `/patterns/rank-topology-3d/`。

