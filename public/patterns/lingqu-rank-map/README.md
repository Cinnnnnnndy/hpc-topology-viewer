## 它是什么

一条下钻链 + 三张常驻悬浮卡 + 一块可缩放的画布。打开就是**集群**：4096 张卡物理上怎么连（灵衢的超节点 /
L2 平面 / L1 交换 / POD / 板上的 NPU·CPU·DPU·NIC），NPU 按 PP 段着色——并行拓扑已经叠在物理图上；往里
是**段**（一条 PP 段在模型里怎么分组）、**卡**（这张 rank 的层区间/显存/物理位置/通信组走哪一级）、
**单卡**（矩阵本体的 solo 渲染）。四层用同一套 chrome：顶栏面包屑、左卡、右卡、底卡一直在，只换内容。

默认预置 **moe504b32k**（`tp4·cp8·pp8·dp16·ep16`，world=4096）——pangu_sophon_pytorch 项目
`config/llm/moe_504B_A18B/` 里 32K 序列那档的真实切分（504B 总参/18B 激活）。`dp=16` 不是猜的：项目代码里
`data_parallel_size = world_size ÷ (TP×PP×CP)`，EP 落在 DP 域内、必须整除 DP，`DP=EP=16` 是这组切分的最小
合法值。默认预置先后改过三次（pangu → moe718b128k → dense64 → moe504b32k），每次的原话与取舍见 `pattern.js`
「默认预置」那段注释；四档旧预置都没删，`?preset=` 照样认得。

## 故事线：集群 → 板 → 卡 → 单卡

反馈「按下钻的逻辑把整个视图串起来，而不是视图 tab 切换」。不再有并列的画法切换，画布停在哪一层由
下钻状态决定：

1. **集群**（默认第一屏）——灵衢物理拓扑，内联 SVG。滚轮以指针为中心缩放、拖拽平移；点一个 POD 或
   超节点取景过去，点空白复位。点一颗 NPU = 选中 rank（进「卡」）。
1′. **板**——POD 取景之后再点它里面的一行，或右卡「→ 板 N」：画布换成这块板的 Server 形态图（下一节的
   表里「板」那一行的全部关系，一处不落）。板上点 NPU = 选中 rank；面包屑 `集群 › 板 158 › rank 1267`。
2. ~~段~~——**已撤下并归档**（反馈「这个视图先不做，归档到另一个分支，起个名字放启动页」）：宇宙视图 / 径向星图
   整份代码在分支 `claude/pp-segment-radial-archive`，发布为 [`/patterns/pp-segment-radial/`](../pp-segment-radial/pattern.html)
   （启动页有卡片，main 的 deploy 工作流按 ref 取过来叠加）。本页左卡的 PP 段按钮现在是**原地聚焦**那一段
   （其余段压暗，再点取消），不换画布。
3. **卡**——任一层选中之后右卡先摆坐标行（不留空白），紧接着借矩阵本体一次不铺屏的 `?brief=1&sel=`
   请求（`ptoRankBrief()`，跟第四层读的是同一份口径）把层区间/显存构成算回来，原地升级；再加物理位置
   与五个通信组各走哪一级链路。
4. **单卡**——「↓ 单卡下钻」换到矩阵本体（`fastcard=1&solo=1`）：真实容量读出、显存构成（原色）、卡内那一级
   通信。矩阵里点空白退出 solo，`pto:tier` 报回来，这一层退到上一层，不重新加载。

顶栏胶囊只放面包屑：`集群 › rank 1271 › 单卡` 或 `集群 › 板 158 › rank 1267 › 单卡`，每一级都能点回去
（回板层保留选中、回集群清掉）。

**ZeRO 档位**（反馈「红色这么多，一下告警会有这么多红色么？」）：矩阵本体的显存估算默认不切优化器（ZeRO-0），
每卡存一整份 fp32 优化器态（约 46 GB），默认预置 4096 张里 3959 张顶出 64 GB。这不是这套配置真实会报的告警：
Megatron 系训练大 MoE 常规开分布式优化器（等价 ZeRO-1，优化器态沿 DP 切 16 份），开了之后全部卡在 32–42%。
所以 moe504b32k 在本页默认 `zero=1`（**假设**——504B 那份 yaml 不在本仓库，没逐字核对 `use_distributed_optimizer`），
第一屏是暗灰，红色只留给真告警。左列图例下有 `zero 0 1 2 3` 一排小按钮，切到 0 就能看到「不开会爆显存」的对比；
档位写进 URL（`?zero=0`），传给矩阵的三种请求（集群聚合、选中卡读数、单卡层）都带上。

| zero | 超容 | 逼近红线 | 占用率中位 / 最高 |
|---|---|---|---|
| 0 | 3959 | 137 | 103% / 113% |
| 1（默认） | 0 | 0 | 35% / 42% |
| 2 | 0 | 0 | 24% / 30% |
| 3 | 0 | 0 | 16% / 23% |

**落位是假设**：配置里没有 rank→NPU 的映射，这一层按「rank 连续摆放」推（`r → 超节点 ⌊r/1024⌋ · POD ⌊r/64⌋ ·
板 ⌊r/8⌋ · 槽 r%8`），左卡与右卡都写明。在这条假设下能算出真东西——五个通信组的成员由矩阵本体的
`rankOf = ((pp·DP+dp)·CP+cp)·TP+tp` 反算，组内最远的一对落在同一块板 / 同一个 POD / 同一个超节点 / 跨超节点，
就是它走的那一级：默认预置里 TP（4 卡）永远在板内 fullmesh，CP（32 卡）在半个 POD 内走 L1，EP=DP（16 副本）
跨 8 个 POD 走 L2 平面，PP 相邻段每两段跨一次超节点走 UBoE。选中一张卡，它的五个组成员保持原灰度、其余压暗，组别只靠描边线型分
（TP 白实线、CP 灰实线、EP/DP 灰虚线、PP 深灰虚线）；
EP 与 DP 成员完全一样时（DP=EP）合成一行，不摆两行一样的话。

## 真实故障复盘（两条链）

反馈「这些数值卡片就是应该直接出现在进去的第 1 个视图中」「不要靠 tab 切换看数值，空值横杠不要显示」
「不要堆砌在最下方，以悬浮卡片分布在画布四周，最好有一个链路式」「先只出现问题，点击问题再出现相关的
链路」——两条问题线各一张问题卡（名字 · 事件数 · 根因），问题2 挂左卡下、问题1 挂右卡下；点问题卡才在
它下面展开这条线的事件链（一条从上往下的时间线，每个事件一张小卡：时刻、标题、根因标记、只写这一刻
真采到的读数，`BOARD` 里 `s==='na'` 的「—」占位不画；结论与来源收进 hover）。数据逐字抄自
`/incident-canvas/` 的 `GROUPS`/`TRAIN_METRICS`/`BOARD`（那份本身照抄 compute-graph-viewer 的
`INCIDENT_GROUPS`）。这是**另一次独立的 2048 卡训练**的真实事故，跟当前预置无关，页脚直说；有具体 rank
的事件带一颗按钮：当前预置是 `incident2048` 时就地下钻，否则整页跳转到 `?preset=incident2048&sel=N`——
事件里的 rank 号是那张 2048 卡拓扑坐标系里的，在当前预置里不是同一张卡，不假装能就地下钻。

`incident2048` 那档的切分（`tp1·pp4·dp512·ep64`）是从事故原文的拓扑常量（`pp=4·edp=8·ep=64`）反推的：
world=pp×edp×ep=2048，本页公式 world=tp×cp×pp×dp，故 dp=edp×ep=512、ep=64——唯一能让 demo.html 自己的
`rankOf`/`epOf` 算出跟原文一致 rank 号的取法（`rank 1559 → pp3·ep23`、`rank 1553 → pp3·ep17`）。

## 两套 rank 编号

逻辑魔方与并行拓扑矩阵各自独立实现了一遍「rank ↔ (tp, cp, pp, dp) 坐标」的换算，内部打包顺序不一样：

| | 打包公式 |
|---|---|
| 逻辑魔方 `pattern.js` | `rank = ((rep × PP + pp) × CP + cp) × TP + tp` |
| 并行拓扑 `demo.html` | `rank = ((pp × DP + dp) × CP + cp) × TP + tp` |

同一个数字在两个系统里指的不是同一张卡，必须按坐标四元组换算（`rubikSelToMatrixSel()`）。这一层的物理
画法与宇宙视图都直接用矩阵本体的编号，只有逻辑魔方抽屉报上来的选中要换算。已验证：pangu 预置逻辑魔方
rank 830（`tp6·pp3·rep20`）→ 矩阵 rank 2566，矩阵读出 `tp6·cp0·dp20·pp3`；moe718b128k（CP=16）逻辑魔方
`tp3·cp9·pp8·rep2` → 矩阵 rank 4427，读出 `tp3·cp9·dp2·pp8`，逐位一致。

## 单卡层的兄弟 rank

反馈「旁边隐约画出兄弟 rank，加一个打开兄弟 rank 的按钮，打开后放出并行视图的兄弟联动——不直接放是因为超大集群里
rank 太多」「其他 rank 弱化，只有选中的显示内部容量；点到其他 rank 再把它详细显示」「通信的操作也搬过来，关系和连线
去掉标签简化显示」。矩阵本体多两个 opt-in（`sibs=ghost|on`、`clbl=0`，外加宿主消息 `pto:solo`，都只有本页传）：

- 默认「隐约」：solo 档里兄弟 rank（沿落下的刀与选中同组）只画淡壳、不画容量色带，镜头不动——只看得见近旁几只。
- 工具条「兄弟 rank」→「展开」：兄弟壳实一些，镜头退到同组定位那个倍数；通信连线按 rank 粒度连到兄弟上，线上不挂芯片与字。
- 只有选中那只画内部容量；点一只兄弟 = 原地换选它（仍在单卡层，不重载），左列切分卡、右列、面包屑一起换。
- 工具条「通信连线」一键开关；设置「单卡」里还有兄弟档（隐约 / 展开）与 TP/CP/EP/PP/DP 逐维开关。都写回 URL（`sibs`、`comm3`、`commk3`），不重载矩阵。

## 数据卡（训练 / 推理要看什么，按层出，逐类可关）

反馈「训练推理过程中需要哪些数据、不同大小（下钻层级）要看到哪些数据，做成悬浮小卡飘在四周，能通过设置打开/关闭
某种类型——非常重要，做细致的调研」+「把并行拓扑里点开 rank 那张卡拆开，每个小切分和对应数值做成单独的卡，放在
单卡视图四周」。调研来源：`research/` 的学习笔记（训练监控设计文档的模式 A/B 指标、昇腾监控 ingest 数据源清单、
算子并行框架融合改进方案 §9 的异常形状→根因、§12 推理 H²P 的时间切片语义）、并行拓扑 `demo.html` 的配置面板
（数据标注五键、通信粒度、观察层级）与整网图逐算子读数、`src/scene/data.ts` 的 `STEP_DECOMP` / `WORKLOAD`。

九类，设置浮层「数据卡」逐类开关（`?dhide=`），工况 训练 / 推理（`?mode=infer`）：

| 键 | 名称 | 内容 | 口径 |
|---|---|---|---|
| `cap` | 容量 | 集群：四档分布 + 最满那张；POD：峰值/均值/超容张数；板：八卡逐张占用条 | 实算（`ptoClusterBrief`） |
| `state` | 显存各档 | 单卡层：权重 / 梯度 / 优化器态 / AllGather 窗口 / 激活 / 优化器步临时区 / 碎片，每档一张，带归属与相位、ZeRO 切几份 | 实算（`ptoRankBrief().detail`，与矩阵读出卡同一批函数） |
| `wshard` | 权重切分 | 单卡层：权重带里逐块一张——哪个算子块、被哪把刀切（TP/EP/复制）、怎么切、多少 GB | 实算（`wCutBlocks`） |
| `comm` | 通信 | 集群：各维在哪一级闭合 + TP/PP/DP 每条边字节 + 载体带宽；POD：本级闭合；rank / 单卡：各维每边载荷（CP/EP 不给数） | 实算（`commLoad9`）+ 落位假设 |
| `pipe` | 流水·气泡 | (PP−1)/GA、每段层数、μbatch；rank 的层区间与 ZeRO 档 | 实算 |
| `phys` | 物理 | 板：H2D / NIC / fullmesh / 出板 / NIC 交换的配对 | 假设（连续落位）+ 直播四页 |
| `step` | 步时 | 训练：计算/通信/访存占比 | 示意（盘古 Pro MoE 报告，800I A2，非本硬件） |
| `infer` | 推理 | 推理工况：prefill / decode 吞吐、TTFT / TPOT、batch、MTP，prefill / decode 各自的步时分解 | 示意（同上；KV cache 未建模） |
| `inc` | 故障复盘 | 左列两条故障链 | 复盘（另一次训练的原文） |

按层出哪几张：集群 = 容量分布 · 通信闭合 · 流水气泡 · 步时（推理工况换推理指标）；POD 取景后 = POD 负载 · 本级闭合；
板 = 八卡占用 · 板载配对；选中 rank = 右卡（显存 / 位置 / 通信组）+ 通信载荷 · 流水；单卡 = 并行拓扑那张 rank 读出卡**拆成小卡，排在
左列、接在配置卡下面往下排**：先模型态（权重 → 逐块切分缩进一级、梯度、优化器态），再执行态（激活、碎片…）；每张可点开，
内容就是并行拓扑读出卡里点开那一块时的那一栏（`memBlockDetail` 原文拆成结构：dt/dd 行、腔图、对应通信、兄弟卡）。右列：
rank 位置与通信组、各维通信载荷、流水。

**消融**（反馈「字太多、只留 key 和 value、不要解释的词语，所有部分做消融，一定要简洁」）：卡面只有名字与数值；
归属/相位、怎么算、为什么——一律收进悬停。口径小标只标例外：默认就是实算，只有「假设」「示意」才挂标。单卡切分小卡
收起时一行（名字 · 切法 · GB），点开后也只有 key/value（每层形状、参数量、层段、切法、通信「维 原语」）+ 一张腔图，
括号说明、整句解释、兄弟卡那句都不上卡。

## 泳道（本预置的 1F1B，与集群联动）

反馈「修改泳道的数据，让它也可以和上面的集群联动」。原来嵌的是 combo-workbench 的上游泳道（compute-graph-viewer 拷贝），
画的是它自己那份 32 卡示例（PP4·TP2·EP2、手写时间与事件），段号、rank 号都对不上本预置，接不起来；那份页面不改（它还在
组合工作台里用），这里换成本页原生的一张 SVG：

- 每个 PP 段一条道（`PP2 L12–17`），道上是这一段处理的全部 GA 个 micro-batch：前向蓝、反向粉，按标准 1F1B（第 p 段先灌
  PP−p−1 个前向，之后一前一后，最后排空）逐个解依赖排出来；空着的就是气泡，占比 (PP−1)/GA，与流水卡同一个数。
- 时间以「一个 μb 的前向」为 1、反向按 2：相对时长，不是实测（右下角「示意 · B=2F」）。
- 选中 rank：它所在的那一段亮起，下面多一条它自己的道，绿竖线 = 段边界收发激活 / 梯度，末尾绿块 = 步末 DP 梯度同步。
- 点一条道 = 聚焦那一段（集群画布上其余段压暗），再点取消；悬停一个 μb，它在各段上的前向反向一起亮。
- 颜色沿用泳道原来那几种（蓝 / 粉 / 绿），其余仍是灰阶。

## 跨视图联动

集群 / 板画布、逻辑魔方、整网图、泳道、层级剖面是同一个选中：宿主是唯一的选中源，`curSel`（rank）/ `focusPP`（段）
一变就推给开着的面板，面板里点了也折回同一条路。魔方走 `rubik-cmd select`（`rubik-pattern.html` 只多认这一条宿主指令，
不发就不动）⇄ `rubik-select`；整网图走 `pto:state hl.rank`（同一个矩阵预置，rank 号一致）⇄ `pto:select`；泳道与层级剖面
是本页原生，重画即高亮、点一段 / 一格即聚焦或选中。面板报上来的那次改动不回推同一个面板（防回声）。

## 连线样式

照 hpc-topology-node「硬件图元库 · 连线样式」的结构去色：每条稀疏干线 = 底色衬边 + 芯线，芯线的实/虚节奏区分介质
（铜缆实线、光 UB 虚线 7 5、UBoE 稀虚线 4 7 半透明、RoCE 3 3 + 端头空心环、PCIe 点线）；两端是 marker 端口环（底色实心环 +
灰描边 + 中心点），并进总线的一头是实心汇接点，随线宽缩放。太细时换显示方式：集群总览线宽不到 1px，不画衬边、RoCE 收成
实线压淡；成束的密线（出板 Clos 64 根、fullmesh 28 根）平时只是发丝线，只有选中那颗 NPU 的那几根换成白色激活样式，板视图里
还有两颗小点顺着线跑（板内快、出板慢）。POD 形态图里的 **NIC 交换**（SW·4N，1 口/C、2 口/N）与 **框内 L2 交换板**（2×SW ×2，
每颗 L1 4 口，框内板间互联）补进了板视图与放大后的集群画布。

## 它不回答什么

- **并行度组合切换**——两个本体各自的 preset / 自定义 tp·cp·pp·dp·ep 都还在，这一份把默认值定死在
  moe504b32k，换配置用 `?preset=`。
- **真实的 rank→NPU 落位**——那是调度/启动脚本的事，配置里没有；这里只按连续摆放假设，并且写在脸上。
- **矩阵本体之外的第二套显存/容量算法**——所有数字都借矩阵本体算（`?brief=1`），这一层只摆版式。
