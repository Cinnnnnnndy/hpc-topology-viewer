Pattern · 逻辑重排视图

逻辑魔方LogicalRubikCube

把同一批 rank 按不同并行轴「换一种堆法」的 3D 重排视图：五种形态共享一套布局规则， 切形态即换投影轴并以飞行动画重排，用形状回答「谁和谁一组」「这批异常属于哪一维」。

IDrubik-cube-logical 类型renderer 默认预设TP8 · PP5 · DP100 · EP2 = 4000 rank 设计系统PTO Design System 主题浅色默认 · 明暗联动

01场景说明必填

逻辑魔方把一个训练/推理作业里的每一张加速卡（rank）画成一个恒定大小的小方块： 1 小块 = 1 卡 = (TP, PP, DP) 坐标的交点，另叠一层 EP 桶身份。 整堆卡可以按不同并行轴重新堆放——这就是「形态」。切形态只换投影轴、不改变卡本身， 卡群以 0.5s 飞行动画落到新位置。

它解决的问题：大规模并行作业里「谁和谁一组」是四维关系（TP / PP / DP / EP）， 一张二维表或一张物理拓扑图只能表达其中一层；而现场真正要回答的问题是 「这批异常卡属于哪一维」「这一维的通信此刻在跟谁收发」。 逻辑魔方把维度关系变成空间形状：异常若沿某一维成组，切到对应形态就 snap 成一整块 （一面墙 / 一块板 / 一整段），根因类别当场可见。

四个维度分别是什么

维度含义在魔方里的表现签名色
TP张量并行：同一层被切成 N 片，片间每层做 AllReduce标准形态的 X 轴；TP切片形态里每片是一面墙青 --dim-tp
PP流水并行：模型按层切成 N 段，段间 P2P 接力标准形态的 Y 轴（模型深度，上→下）橙 --warning
DP数据并行：N 个完整副本，步末做梯度 AllReduce标准形态的 Z 轴；DP平铺形态里每副本是一块板蓝 --primary
EP专家并行：MoE 专家分桶，桶间 AllToAll不占独立轴，折入 DP 轴：副本 rep 持桶 rep % ep紫 --highlight-l0a-violet-400

rank 总数 = tp × pp × dp；EP 不参与乘法，只要求整除 dp。 相邻 ep 个副本构成一个 AllToAll 域，共 dp / ep 个域。

它不负责什么。不画物理拓扑几何（机柜、线缆走向、板卡内部结构）——那是硬件拓扑视图与图元库的分工； 不做精确数值比较——那是图表的分工。逻辑魔方只讲逻辑分组，物理落位只以「着色透镜 + 文字」的方式出现 （见 03 场景设计）。

02场景引导必填

入局设计师用三个问题判断该不该用这个 Pattern：

  1. 对象是不是「同一批同构单元」？——rank / 卡 / 实例，成千上万个，个体没有独立形状。
  2. 它们之间是不是多维分组关系？——同一个个体同时属于 2 个及以上分组维度（TP 组、PP 段、DP 副本、EP 桶）。
  3. 用户要回答的是不是「形状问题」？——谁和谁一组、异常属于哪一维、这一维此刻在跟谁通信。

三个都为「是」→ 用逻辑魔方。任意一个为「否」→ 见下表的替代方案。

该用（Use When）

页面要回答的问题逻辑魔方怎么答
这批异常卡是同一个 TP 槽位坏了，还是某个副本慢了？注入/着色后逐个形态切换，异常 snap 成整块的那个形态就是根因类别
选中的这张卡，它的四个通信域各是谁？选中 rank → TP/PP/DP/EP 四组同屏高亮，重排飞行时跟随
一个训练 step 里，热点什么时候在哪一维？时间轴 = 4 个通信阶段，热力场随阶段变形，主导维加亮
这一维的集合通信按什么算法收发？Ring（前半 ReduceScatter / 后半 AllGather）/ Tree / P2P 链 / AllToAll，可切换对照
逻辑分组和物理落位对得上吗？按主机 / Pod 着色看 rail 亲和；详情卡给「此刻这一维走线各跨了哪层」
换一套并行度会变成什么样？输入 TP/PP/DP/EP 即时重建，布局由规则推导，任何数字都自动排好

不该用（Don't Use When）

场景为什么不合适改用
只有一个分组维度（例如纯 DP 的推理集群）重排没有对象，五个形态会退化成同一张图列表 / 热力表
要看链路走向、端口、机柜与线缆本 Pattern 明确不搬运物理拓扑几何硬件拓扑视图
要精确比较数值（吞吐、时延曲线）3D 里的色差读不出量级差图表 / 指标看板
要看单卡内部结构（NPU / HBM / 片上互联）一张卡在这里是不可再分的最小块Node / 芯片视图
要看长时间跨度的趋势与事件序列时间轴只表达一个 step 内的 4 个通信阶段时序泳道
规模极小（< 16 卡）且只关心逐卡明细形状信息不足以支撑重排，表格更直接表格

接入前要准备的输入

输入必需说明
tp / pp / dp / ep必需并行度。校验：四数 ≥ 1、ep 整除 dp、tp×pp×dp ≤ 65536
layers / experts可选模型层数（默认 48）与专家总数（默认 64），决定 PP 段的层标尺与桶内专家号
hotBuckets可选热点桶号，用暖色标出
placement可选物理落位 {cardsPerHost, hostsPerPod} 或 slots；默认 8 卡/机 · 32 机/Pod、rank 连号装机
onSelect / onSelectEdge可选选中卡 / 选中一条通信边的回调，宿主据此联动自己的视图
规模适配。布局规则已在 1 卡至 8192 卡（含 tp=1 / tp=32 / pp=60 等退化与极端形状）× 5 形态上逐对包围盒验证：零重叠。 超过 65536 rank 会拒绝应用并报错——不是渲染不动，而是那个规模下「逐卡可读」这个前提本身不成立，应先在上层做聚合。

03场景设计必填

3.1 画面结构

整个 Pattern 是一块画布 + 四组浮层。浮层一律浮在画布上，不切分画布——3D 场景的取景会自动为浮层留白 （chrome:false 嵌入时由宿主接管工具栏，也不再留白）。

区块位置放什么 / 不放什么
① 名称顶栏左裸文字浮在画面上，不套卡片——叠两层底会让底色发虚
② 配置顶栏右常驻只有「形态」「视角」两组 segmented-control（选中态 --primary）+ 播放 + 「更多」抽屉 + 宿主控件插槽。着色 / 注入 / 连线 / 时间 / 并行一律进抽屉
③ 详情卡画布左侧选中一张卡后出现，结构见 3.7；右上角 × 取消选中
④ 图例画布右下分「着色 / 连线」两段，一行一条，只有色块 + 名字；读法与为什么不写在这里
⑤ 阶段轨道画布底部悬停弹出，可拖拽定位；播放/暂停常驻顶栏
问号气泡各控件行首承载「这排是什么、和别的排什么关系」，随当前形态 / 注入 / 选中态更新

3.2 五种形态

形态只改变卡摆在哪（谁挨着谁），不改变卡本身、也不改变颜色。 哪一维被堆成一整块，那一维的问题就现出形状。

形态怎么摆回答什么问题异常长什么样
标准
std		X=TP · Y=PP · Z=DP一张卡的三维身份、整体规模；位置即多维坐标各维都看得见，但都不成块
DP平铺
dpt		每副本一块板，板排成宫格（板内 TP 折成 列×排）哪个副本慢 / 掉队（副本间只在步末做梯度 AllReduce）宫格里干净的一块板全红
EP聚簇
ep		每个专家桶一面墙，A2A 域横穿各墙热点桶 / 桶故障 / 域热点（桶 ↔ 卡非 1:1）一整面墙同红；域热点 = 横穿各墙的一排过热
TP切片
tps		每个 TP 槽位一片权重墙，墙间拉开同槽位系统性故障（整批同号卡坏件）一面墙集体异常
PP流水
ppf		PP 段横向展开，左 S0 → 右 Sn-1慢段 / 流水气泡（慢段拖住下游）一整段全红，右侧板随之变暗；空档 = bubble

3.3 视角与剖面

轴测 3D 可拖拽旋转；顶 / 前 / 侧是正交锁轴的 2D 投影，会把与视线平行的维折叠。 视角按「每个 2D 平面只属于一个形态」收编：与标准形态坐标系重合的形态不再重复给出 2D， 并在视角行说明原因。任何正交视角下拖动即从当前朝向无缝转回 3D。

形态轴测 3D顶前侧
标准✓DP×TPTP×PPDP×PP
DP平铺✓副本网格列×PP行×PP
EP聚簇✓桶×域桶×PP域×PP
TP切片✓2D 与标准重合 → 收编（价值在 3D 的「墙拉开」读法）
PP流水✓2D 与标准重合 → 收编（价值在 3D 的「段拉开」读法）

折叠必须如实标注：每个正交视角给出粒度贴士「每格重叠卡数 = 各折叠维成员数之积」 （例：EP聚簇侧视 = 专家桶 2 × TP 8 = 16 张卡重叠）。 剖面按最外层折叠维逐层翻，只看某一层、其余压暗。

3.4 时间轴 = 一个训练 step 的 4 个通信阶段

时间轴按阶段读，而不是抽象的秒——每个阶段由哪根并行轴主导、走哪层总线、负载多高都不同。

阶段主导维集合原语走哪层总线负载
TP · 前向 AllReduceTPAllReduce（Ring / Tree）节点内 UB · 高频0.92
PP · 阶段接力PPP2P Send/Recv 接力链Pod 内跨 Host · 中频0.45
EP · MoE 浪涌EPAllToAllPod 内全互联 · 浪涌0.88
DP · 梯度 AllReduceDPAllReduce（Ring / Tree）跨 Pod Scale-Out · 低频大包0.60

一个 step = 12s（每阶段 3s）。热力场随阶段变形：TP 组齐动 / PP 接力波沿流水级前进 / EP 浪涌点亮热点桶 / DP 全网梯度；选中卡的四维通信组里，当前阶段主导的那一维加亮，其余淡显。

3.5 通信组与走线

连线按集合原语的实际算法画，五个图层各自独立开关（可全关）：

图层画什么规则
成员同域对端卡的标记只有棱的线框，不用半透明外罩——罩色会和卡自己的着色相叠
通信线Ring / Tree / P2P 链 / AllToAll 的走线逐段直线，顶点严格落在卡心；只有长边（Ring 闭合边、Tree 跨层边）画成两端落在卡心的外凸弧
域轮廓把整组用线框包起来切到对应形态时组 snap 成整块，轮廓直接画出「这组在这种堆法下是什么形状」
粒子沿此刻主导维走线跑的流动暗点方向由点的流向表达，不画箭头；快慢对应该阶段的通信节奏
聚焦无关卡压暗并缩到 0.42，网格反过来加强几千张卡各自有色时，四维高亮会被整片颜色淹没

3.6 着色透镜、异常注入与物理落位

着色是给卡上色的镜头，只改颜色不改结构：状态热力（跟着阶段走的绿→黄→红）/ 按 TP·PP·DP·EP 分组 / 按主机·Pod 分组（物理落位透镜）。注入不是另一种镜头，而是接管着色—— 一旦注入非「无」，卡色改由故障决定（受影响卡 = --danger，其余按低负载淡色）， 着色镜头暂时让位、图例同步切换，选回「无」即恢复。

色的用途取自约束
负载热力--success → --warning → --danger 三段插值与图例那条色带同源，颜色逐格一致
异常组--danger红黄绿是状态色专用，其他语义不得占用
分组着色highlight 六族的 400 / 600 两档共 12 色循环组数超过色环时图例注明「同色非同组」
维度签名色TP --dim-tp · PP --warning · DP --primary · EP --highlight-l0a-violet-400画在网格与走线上，不画在卡面
物理链路层级同机 UB ub-green · Pod 内 rail mte-amber · 跨 Pod l0b-deep-violet-600只出现在文字与悬停提示里，不画成 3D 细线或包围框
网格 / 外框 / 字牌 / 场景底--border-* / --surface-* / --backgroundThree.js 吃不了 CSS 变量 → 挂载与切主题时 readTokens() 解析成色值

同一件事只在一个地方说，按「看多久」分配位置：

承载位置放什么不放什么

4.8 速查：还有哪些明确禁止

禁止为什么
在宿主里逐形态手调间距常量布局必须由规则推导；改规则不改调用点，否则换一组并行度就全乱
把 EP 当独立轴乘进 rank 数EP 折入 DP 轴，只要求整除 dp；乘进去会得到不存在的卡
复制渲染后的 DOM / 几何到新页面必须调用 mount()，否则拿不到重排、联动与后续修复
硬编码颜色 / 圆角 / 阴影 / 间距，或自造按钮与面板一律 token 与 .btn / .panel-shell / .stat-chip；3D 材质色必须经 readTokens()
用 emoji 或装饰字形当图标（▶ ⏸ ▦ ◇）图标一律内联 SVG，stroke=currentColor
用箭头表达方向方向由沿线流动的暗点表达；箭头在正交画面里抢眼且与卡块语言不搭
把物理层级画成 3D 细线或包围框试过：线太细、机的范围与 TP 组几乎重合，读不出差别 → 改用文字与矩阵
把解释写进图例图例只列颜色与名字，读法进问号气泡

5.3 允许改 / 不允许改

允许覆盖禁止覆盖
并行度与工况（config / layers / experts / hotBuckets / placement）；初始形态与主题；chrome:false 由宿主接管工具栏；容器外的排版与外框；页面级 token 覆盖 宿主 CSS 里覆盖 .prc-* 的具体色值；逐形态手调间距常量；直接改 pattern 内部状态（联动一律走 selectLayer / selectBucket / onSelect）
改动后必跑：scripts/verify-rubik-cube.mjs——两套配置 × 五形态，断言每条通信线的每个折线顶点都落在对应 rank 的卡心。 涉及连线几何或重排动画的改动尤其不要跳过（这个问题复发过三次，成因各不相同）。

06设计原则非必填

规则的价值在于：换任何并行数字都自动成立，新增维度（CP / SP…）或新增形态只需按同样规则声明轴的意图，不引入新的魔法数字。

原则名称描述说明应用建议
① 卡块恒定 一张卡是恒定的正方体，换形态、换配置都不改变它的大小与形状。 卡块几何与取景留白都以它为唯一事实源；需要「更好看的比例」时改的是步距，不是卡。
② 步距由规则推导 单维轴步距 = 卡块尺寸 + 缝隙(成员数) × 层级倍率。缝隙按成员数分档（多则紧、少则松），层级倍率表达意图：dense / normal / spread / emph。 新增一根轴时只声明「成员数」和「意图」，不要写死数值；长轴不被拉成细丝，短轴不退化成薄片。
③ 复合轴分块 外维分块 + 内维紧邻：外维步距 = 内维总跨度 + 随跨度成比例的块间留白。 板 / 墙一类结构一律这样声明，任何规模下块与块都清楚分开。
④ 2D 可读性 3D 摆法必须同时对每个正交视角成立：任一视角下屏幕两轴的最细步距之比 ≤ 4；会退化成薄片的内维折成 2D。 出图前把顶 / 前 / 侧都过一遍；出现稀疏条纹就是这条被违反了。
⑤ 网格即语义 网格线一律画在格边界上（卡落在格子里、不被线穿过）；一根轴的格边界用该维签名色画，轴向不画任何裸线与箭头；选中聚焦时网格整体提亮。 方向交给刻度标与文案（L1（上）→L48（下））；分组行列数按世界跨度取近方形，不按数量取方阵。
⑥ 视角收编 · 如实折叠 每个 2D 平面只属于一个形态；信息塌陷的视角不给出并说明原因；保留的视角必须报出每格重叠卡数。 宁可少给一个视角，也不要给一个会让人读错的视角；需要逐层看就用剖面。
⑦ 色出一源 所有颜色来自设计系统 token；3D 材质在挂载与切主题时由 readTokens() 解析 token 得到色值。红黄绿是状态色专用。 图例与画面因此天然一致；缺色族（如 TP 的青）由 pattern 自备并标记「待回补上游」，不要就地造一套 HSL。
⑧ 注释纪律 3D 里只留短标记，整句解释进问号气泡；字牌随场景缩放但有屏幕像素地板；语义色只落在名字上，注释对比度低于模型本身。 标记贴着它标注的那根格线走；标记若必须坐在模型外，用中性引线牵回锚点，不要盖在卡上。
⑨ 走线三层 casing（底色外套）+ 彩色线芯 + 流动暗点；方向只由点的流向表达；点的快慢对应该阶段的通信节奏。 直线折线逐段建管保证顶点精确，只有长边画成两端落在卡心的外凸弧；改完跑回归脚本。
⑩ 界面分工 常驻只留决定画面怎么摆的控件（形态 / 视角），筛选与工况收进抽屉；图例只列颜色与名字；详情卡按 inspector 结构给「定义 · 当前值 · 状态判断 · 执行上下文」。 任何想常驻在画面上的解释性文字，先问一句「它能不能进问号气泡」。

08FAQ拓展

EP 为什么不乘进 rank 总数？

EP 折入 DP 轴、不新增轴：副本 rep 持有专家桶 rep % ep，相邻 ep 个副本构成一个 AllToAll 域。所以 rank = tp × pp × dp，ep 只要求整除 dp。默认配置 8·5·100·2 = 4000 rank、2 个桶、50 个 A2A 域。

TP切片 / PP流水 为什么没有 2D 视角？

它们与标准形态共享坐标系，正交 2D 投影完全重合——给出来只是同一张图的三份副本，还会让人以为是别的东西。价值在 3D 的「墙拉开 / 段拉开」读法，因此整组视角不显示（只剩一个孤零零的「3D」按钮既无可切换对象，也像是别的被禁用了），并在视角行说明原因。

4000 卡会不会卡？

重排缓动按时间算（0.5s，与帧率无关）并在收尾精确吸附，所以低帧率下卡与线仍然落到位；走线逐段建管、成员框合并进同一条 LineSegments。布局已在 1 至 8192 卡上验证零重叠，超过 65536 rank 会拒绝应用。

能不能改配色 / 换成业务自己的品牌色？

可以，但只能在页面级覆盖设计系统 token——pattern 只消费语义 token，3D 材质也经 readTokens() 读同一批 token，所以覆盖后画面与图例会一起变。禁止在宿主 CSS 里覆盖 .prc-* 的具体色值。

只想嵌一块画布、工具栏用我自己的，怎么做？

mount(el, { chrome: false })：pattern 不再渲染自带工具栏，取景也不为面板留白，全部控制走 handle 上的 setMode / setView / setColorBy … 一组 API。

要新增一个并行维度（CP / SP）怎么办？

不要新写一套坐标计算。在 pattern.js 的 SP / modes 里按原则 ①–⑥ 声明这根轴的意图（放哪根轴、用什么层级倍率、正交视角折叠哪些维），布局会自动推导出来；同时补上该维的签名色与图例条目。
