**评估日期** 2026-09-10 · 逐节判断参照系 20 节 + PRD + 附属文档 + 七个 pattern 哪些是原创主张、哪些是复述已知

## 参照系 §00–§10

**最强的原创点（按强度排序）**

- §07 的「三能力判据」：并行切分的落点必须同时具备私有地址空间、通信端点、独立执行流；物理五级里只有卡三项全齐 → 「地址空间的边界在哪里，并行的落点就在哪里」。附带的四个压力测试（MIG 必须先改造成卡等价物、超节点只松弛约束不改落点、ZeRO 分片单位仍是 rank、offload 归属记账没离开 rank）把它从观察提升成判据。这是全文最像定理的一段。
- §02 的「归属边界」概念 + 通则「通信算子恰好插在归属边界上」，并由此把 §04 的嵌套顺序从经验规则降格为边界深度的直接推论（TP 边界在 kernel 最深 → 必须机内；DP 边界仍在整网 → 可跨机最外层）。这是把五种并行统一在一个坐标上的唯一一处理论化尝试。
- §01 的基数方法论：同一对实体（层 → 卡）在四种配置下有四种基数，且「纯 TP 与纯 DP 基数完全相同但语义相反」——由此得出「基数只回答几对几、不回答是什么关系」，判据要另立（§06 的「单卡能否独立算出这一层」）。这条直接支撑 N:M 不压平的主张。
- §09 的解绑：并行维度 ⇏ 通信原语，真正决定原语的是切口两侧的数学关系（求和维/拼接维/归属维/前后依赖四分），链条是两层且后两步多选一。CP 一维三原语（P2P / All-to-All / AllGather）是不可辩驳的反例，且带出可验证的治理代价（非标准实现下按名字反查原语会带偏定位）。
- §10 的「rank 是地址不是身份」+ SPMD 成立的全部两个条件（图不被切 + rank 是纯地址），以及「两张卡一样不一样」判据表——其中 DP 与 CP 在权重体侧行为完全一致，反过来成为 §05「CP 是会漏的 DP」的硬证据。这是 P3「地址不是形状」最直接的根。
- §07 的「切整网从来没有真的发生过」：没有分发者，每张卡按 rank 各自少建；门牌号不是卡固有的而是 initialize_model_parallel 算出来的，验证方式是「换个 order 同一张物理卡门牌号就变」。这条既纠正一个普遍误解，又给出了可证伪的验证手段。
- §07 的「四刀是门牌号的四个数位，不是四道工序」，以及随后的三层顺序拆解（切分结果冻结 / order 线性化全程不变 / 只有 PP 有执行因果），加上唯一动态例外是 MoE token 路由（且只有激活侧动态、权重侧 expert 放置仍是初始化定死）。
- §03 的封闭性主张：「能切的东西一共只有五样」，且 world_size = TP × CP × PP × DP 恰好因为 ℓ h b s 四根轴全网都有、e 时有时无撑不起乘数——这给了「EP 不是第五个并行维度」一个结构性理由，而不是实现细节的理由。
- §03 推论三：「切分的全部痕迹，就是单卡 shape 上的除号」。把整套并行压缩成一句可验证的话，且明确划出边界（卡内 tiling 不跨卡、不通信、不改语义，与并行无关）。
- §03 与 §07 的诚实标注文化本身：把「有外部文献支撑 / 只与某一份实现一致 / 纯属本文推理无外部依据」分三层写出来（viewer 排布顺序那一段），并保留 15 条勘误。作为论文的方法论姿态，这一点可以单独说。

**教科书内容 / 写进论文会被批的部分**

- §04 的 TP 列切-行切配对、按 head 切 QKV、GeLU(a+b) ≠ GeLU(a)+GeLU(b) 的论证——这是 Megatron-LM (Shoeybi et al. 2019) 的原文内容，一字不差属于复述。写进论文必须明确标为背景。
- §04/§05 的 SP 机制（AllReduce = ReduceScatter + AllGather、通信量不变、激活省 TP 倍、TP>1 默认开 SP）——Korthikanti et al. 2022 的核心结论，不能当自己的发现。
- §03 的 16 B/参数拆分与 ZeRO 三级切分顺序——文档自己已引 Rajbhandari et al. 2020，但整段展开（m/v 为何 fp32、master weight 为何必需）是 Mixed Precision Training 的复述，篇幅占比过高，容易让审稿人觉得在凑内容。
- §03 的 34·B·S·H 每层激活估算被写成「经验系数」而没有出处——这是 Korthikanti et al. 2022 的公式，未标注会被直接批为不严谨。
- §02 的粒度链（整网→层→算子→kernel）、算子选择 / 算子融合 / tiling / 静态 vs 动态 shape——通用编译器教科书内容，只有「kernel 是唯一交点」那一句是自己的。
- §05 的 Ring Attention 三步环传与 online softmax 约束——Liu et al. 2023 + Dao et al. 2022，属复述；本节真正原创的只有「会漏的 DP」这个定位和「CP 贯穿全部 stage」这个纠错。
- §05 的 CP 经验阈值（s ≤ 32K → CP=1、64–128K → CP=2、≥128K → CP=4+）是文档自估、无实测支撑，文档自己也标了「仅参考量级」。写进论文必须么给实测、要么删掉，否则是最容易被攻击的一处。
- §08 整节：四行表是 §03「共享轴」结论的直接展开，文档自己写了「不必另记」。作为独立章节它没有新知识，只有「DP 加卡不减显存」这句传播性表述。写进论文只能当推论或界面依据。
- §09 后半的硬件栈（NCCL/HCCL/RCCL 三者同层、UB 共享 buffer、机内 300–900 GB/s vs 跨机 100–400 Gbps、TP 必须机内的部署原则）——全部是厂商文档级常识，且与文档自己的「平台无关」主张有点张力：这半节是唯一与硬件绑定的内容。
- §09 的 Ring AllReduce 通信量 2(N−1)/N × S 不随卡数线性增长——Patarasuk & Yuan 2009 的经典结果，写成自己的观察会被立刻指出。
- §10 的 rank / 通信域 / local_rank 基础定义与「一进程多卡、一卡多进程」的例外枚举——MPI 与 torch.distributed 文档内容；本节的价值全在「rank 是地址」那条主张上，定义部分应压缩。
- §06 勘误 D（PP 首尾 stage 因 embedding / lm_head 额外负担而不均、实践做非均匀切分）——这是 Megatron/DeepSpeed 使用者的公开常识，作为「勘误」呈现有点抬高了它的分量。

## 参照系 §11–§20

**最强的原创点（按强度排序）**

- **五类对象本体论（§18）**：结构 / 内容 / 容器 / 地址 / 动作，每类给出判据与视觉语法，并推出「地址是唯一不能具象化的一类」。这是一个可判定、可证伪、可复用的分类体系——给任意一个系统对象都能判出它属于哪类、因而该画成什么。它把 Mackinlay 的 expressiveness 从「数据类型」推到「系统对象类型」，是全文最有可能独立成为论文核心论点的一节。
- **「通信是张量状态的转换」（§15）**：把一次通信定义为「前态分片状态 → 后态分片状态」的变换而非「谁向谁发了多少字节」，并用 Megatron-Core 八个 autograd mapping 函数的官方文档串（每条都写成前向/反向一对）作为一手证据，读出「反向永远是另一个原语」这一规律。配套的跨 rank 三粒度分类（副本之间/分块之间/段与段之间），以「形状变不变」为主轴，直接给出「拿错问法读数全是噪声」的可操作判据。
- **Megatron 官方显存表的数字闭环（§14 二）**：把 Megatron-Core 分布式优化器文档的 20 B→4+16/d、18 B→6+12/d、16 B→8+8/d 三行按 W/G/O 拆开，发现「留在本地的」恰好都 = W＋G、「被除以 d 的」恰好都 = O，从而从官方数字这一侧**独立证明** Megatron 分布式优化器 ≡ ZeRO-1 语义，同时反向验证本文 16 B = 2+2+12 的拆法。这是全文唯一一处真正的独立推导验证，含金量最高。
- **模型态 / 执行态二分（§14 一）**：按「关键属性是归属还是生命周期」而非按「是权重还是激活」来分，并由此推出「两类状态需要两套完全不同的读法——对模型态问区间、对执行态问释放时机」，以及「ZeRO/FSDP 只切左半边」这一有一手文献支撑的边界。
- **「元素数必须由配置界定，不能由数据量界定」（§17 推论 8）**：一条可直接当准则用、且可证伪的可视化可建性判据。配套的「同一条链上不同环节基数差三个数量级，所以必须用三种不同编码」把否定面（不可建）变成了建设性方案。
- **「先后」的四分层（§11）**：把一个会得到自相矛盾答案的问题（切分有没有顺序）拆成数学可交换性 / rank 排布 / 配置依赖链 / 执行时序四问，每问各有确定答案。框架本身原创，且直接解释了为什么这个问题在工程讨论里长期扯不清。
- **「有序维优先上轴、对称维可折叠或分面」（§12 末）**：把「画哪三根轴」从审美选择变成由配置决定的推论——PP 必须上轴（有序）、TP/DP 可折叠（对称，看一个组等于看全部）、CP 视实现而定（Ring 有序上轴、Ulysses 对称可折叠）。
- **「应有 vs 实有」对账表（§14 六）**：应有值只由配置决定、不需跑起来就能先验算出，因而任何偏差都是信号；并论证了「为什么总量曲线诊断不了」——五档相加把「不该变的变了」和「该变的变多了」压成同一条曲线。
- **勘误 K/L 合起来的「维度与原语解绑」**：CP 一个维度就有三种主流实现分别用 P2P / All-to-All / AllGather；EP 的 allgather dispatcher 根本不搬 token。两条实例足以把「TP→AllReduce、PP→P2P、EP→A2A」这类流行写法证伪。

**教科书内容 / 写进论文会被批的部分**

- **§13 整节**是全文最弱环节：它实质上是对某个商用训练可视化产品截图的逐项读数复述。所有「健康范围/参考值」（σ 0.82–1.08、Amax 6.8–9.7、V 0.81–1.07、Δ/W 3.4e-4、W 31.3、Pmax 0.61、H 1.97、balance 0.014、z-loss 0.003、A2A 151 GB/s、mHC Δ% 2.4%/5.9%）**没有任何出处、不可复现、也不可泛化**——它们是一个实例的一次读数，不是经验区间。写进论文会被批为「产品说明文字冒充经验研究」。若要保留，只能作为「某商用工具的一个截图实例」出现，并把所有数值降级为示意。
- **§12 的显存与气泡算术全是教科书**：16 B/参数拆分（Adam 混合精度）、7B → 112 GB、气泡率 (PP−1)/GA、1F1B 峰值 PP 份 vs GPipe GA 份、stage k 压 PP−k 份、算子计算密集/访存密集二分、算子融合的价值——这些在 Megatron / GPipe / ZeRO / 混合精度四篇原论文里都有，必须逐条引用而不能当作本文发现。
- **§11 三的整除约束清单**（num_attention_heads % TP、num_experts % EP、num_layers % PP、seq_len % 2CP、SP ≡ TP、DP 残差）**全部是 Megatron-LM 的现成断言**，属于源码复述。同理五步决策顺序（TP→PP→CP→EP→DP）是 NVIDIA 调优文档的既有建议。真正原创的只是把它们组织成「依赖链」这个说法。
- **§14 二 ZeRO 三级的字节账**（16 → 2+2+12/d → 2+2/d+12/d → 16/d）是 ZeRO 论文的原表。本节的原创在数字闭环验证和「形态差别 vs 程度差别」的读法上，字节账本身不是。
- **§17 推论 1/2/3** 基本是把前文结论换个说法：OOM 与利用率低是两条线索（§12 已说）、每层都慢 vs 某层特别慢（层是最小可区分粒度，接近常识）、算子不支持分三类（工程分诊常识）。作为设计建议成立，作为论文贡献偏薄。
- **§16 勘误 A–J 中的多条是在纠正本文自己的早期草稿口径**（B、C、D、E、H、I、J），对外部读者不构成「流行误解」。把它们与 K/L/M/N/O 并列会稀释后者的分量，也会给审稿人「作者在纠正自己」的观感。建议论文只保留 K、L、M、N、O，并重述为「文献与工程实践中的流行说法」。
- **§19 三「有意划在范围外」** 是范围声明而非研究内容（推理/故障恢复/定量性能模型/框架 API 四条），作为 Limitations 骨架可用，但不能算贡献。
- **§15 六的九层可观测性矩阵**「传统 profiling 只给第 4、5、6、8 行」这句断言**没有给出是对哪个工具、哪个版本的实测**——Nsight Systems、PyTorch Profiler、Chakra/ET 的覆盖面各不相同。这句话很有力，但目前是未验证断言，需要一次具体的工具对照才能写进论文。
- **§12 的 FIG 索引表与「十九张图」自述**属于文档内部导航，与论证无关，进论文需整节删去。

## PRD + 附属文档

**最强的原创点（按强度排序）**

- P3「地址不是形状」+ 验收 A2（在任一视图中找不到任何一个代表 rank 的几何体）。这是全部材料里唯一一条既能推翻现存已发表图示、又能被单个反例证伪、还配了完整下游规范（global_rank 常驻 / 域内 rank 只高亮 / rank 只以标注贴在容器上）的主张。论证链闭合：本体（五类对象）→ 原则（DP-2）→ 规范（§5.3）→ 二值验收（A2）。
- 「维度 ⊗ 原语正交」这一族（P1 + DP-1 + DP-4 + FR-5 + A1）。它有一条极硬的反证物：同一个 CP 维度有三种主流实现，分别用 P2P / All-to-All / AllGather，而 All-to-All 又同时出现在 EP 与 Ulysses CP 上——「维度决定原语」因此被单个反例推翻。而且来源侧留有自我勘误记录（参照系 §16 勘误 K 明确写「§01 基数表原本写对了，正文与图未跟上」），把「基数在传递到视觉层时被压平」记录成了一次可复现的失效过程。
- 第十层「载体」：两套坐标（并行 (tp,cp,pp,dp,ep) × 物理 (超节点,机柜,node,槽位)）的交叉决定这条边走 UB 还是 RoCE，并由此推出可证伪的反直觉结论——超节点内 node 边界不是降速点，换挡点是超节点边界，照直觉画成「node 内快、node 间慢」会画反。三件套齐全：结论可证伪、假设被显式标注（⚠ 不区分板内/板间/机架间，待灵衢团队确认）、假设被隔离在可替换模块里（真有差异只需改 fabricOf 判定与那张带宽表，图与读数结构不动）。这条「把未核实参数隔离在一个判定函数里，使结论的结构部分不依赖它」的做法，本身就是可移植的方法论。
- DP-3「有序维优先上轴，对称维可折叠」+ pp-pipeline 原型。它把「画哪三根轴」从主观选择变成由配置推导（判据是三条：组内成员是否可互换、是否锁步做同样的事、任一时刻是否处于同一位置），并给出折叠可逆的构造性证明（每格摊回 dp×tp 网格，PP 链每跳 global_rank +TP·CP·DP）。核实结论：PRD 那句「已有可交互原型验证这条原则」属实，且原型强于字面描述——它用真解的依赖调度算出 makespan 与气泡，因而自带一条实证发现：1F1B 与 GPipe 的气泡完全一样，差别只在峰值在飞 micro-batch（PP vs micro-batch 数）。
- 「宁缺毋误」从原则落到可检查的行为：CP（逐跳一块 KV）与 EP（top-k 路由当场决定）不给字节数、耗时一律带 ≈、传输时间只给下界写 ≥ 并列出四条免责（未算跳数 / 未算集合通信系数 2(N−1)/N / 未算争用 / 未算协议开销）、配置不整除时舞台封锁并给最近合法值而不静默取整、未选中卡时如实写「没有主语就没有答案」。绝大多数可视化工作在这些地方会选择近似填充，这里逐处选择留白并给出理由，是可以直接展示的差异点。
- 可判定验收体系 A1–A8 + 把误判率提为北极星指标。PRD 自己写下的那句「它是唯一能证明『结构正确』有价值的量化证据——否则『不犯 P1–P4』这件事在评审里很难被看见」，原封不动就是审稿意见，也是论文实验设计的直接依据。
- 跨两份文档的证据分级方法：ub-reference 的四档标注（已核实 12 / 推断 11 / 单一来源需谨慎 12 / 待核实 19）+ §18 把「零命中」这种负面结果也留档 + §16 把知识空白结构化成待补清单并指到具体文档编号。这套做法与 PRD 附录 A 的溯源表是同一种纪律的两个实例，合起来足以支撑一节「设计决策可追溯」的方法论论述。

**教科书内容 / 写进论文会被批的部分**

- §8 视觉编码规范里的线型语义（有方向→实线+箭头、无方向对称→实线闭合无箭头、多对多→细线全连接）与通道色彩固定色相，是 Bertin 视觉变量 / Munzner marks-and-channels 的教科书内容。原创的只是「五类对象与五种语法一一强制绑定 + 每类的禁止项」这层约束，写作时必须把这两者分开，否则整节会被当成常识复述。
- 集合原语语义表（Broadcast / Scatter / Gather / AllGather / Reduce / ReduceScatter / AllReduce / AllToAll 的 before→after，以及 AllReduce = ReduceScatter + AllGather）是 MPI / NCCL 文档内容，nccl-图分析文档里逐条复述且只在文末笼统写了「参考：NVIDIA NCCL / PXN 博客、DGX NVLink 拓扑」，无具体出处。同理，rail-optimized（GPU_i→NIC_i→Leaf_i）与 PXN 换轨机理均为 NVIDIA 已公开博客内容。
- 气泡率 (PP−1)/GA 是 GPipe 论文的公式，不能作为本文结论；「稳态下 stage k 手里压着约 PP−k 份激活」同样是 1F1B/PipeDream 的已知结果。可主张的只有可视化侧的转写（把两个口径并列显示、互为校验）与那条「1F1B 与 GPipe 气泡相同」的实测复现——而后者必须先与原论文口径核对，否则会被当成对已知结果的误述。
- 「传输时间下界 = 载荷 ÷ 带宽」本质是 Hockney / alpha-beta 通信模型里的 beta 项，去掉了 alpha 与算法系数。材料自己列了四条免责是加分项，但公式本身是教科书内容，不能当贡献展示。
- ub-reference 的绝大部分内容（协议栈分层、7 平面、L1/L2 层级、资源池化、产品谱、指标）是对华为公开材料与第三方解读的二手整理，价值在整理方法而不在内容。若把 2.1 μs、16 PB/s、95%+ 线性度、4.37× 时延优势这类数字直接写进论文正文而只引这份手册，等同于二手引用，会被直接指出。
- PRD §2.1 目标表、§3 目标用户与场景表、§10 三阶段分期、§11 里的满意度指标、§12 的 R1（表单地狱）与 R2（三维遮挡）都是标准产品文档套路，没有可主张的学术内容，论文里应压缩成半段背景。
- P2（CP 硬加成第四轴）是四条结构性错误里论证最薄的一条：「两种第四维」这个提法只被命名、没有被定义，PRD 没说清另一种第四维究竟是时间轴还是粒度轴，也没有给出「为什么 CP 不能上轴而 PP 可以」的形式判据（该判据其实在 DP-3 里，但 P2 未引用它）。目前它更接近一条断言加一个解法，而不是完整论证。
- DP-4（视图 × 图层正交）与 DP-5 的后半句（「明确告知为什么画不下」）没有任何对应的验收项——A1–A8 只覆盖了 DP-1、DP-2、P2、P4 与配置校验。五条原则声称「全部从参照系直接推出」并作为裁决依据，但只有三条被验收体系接住，这是可被审稿人一眼看出的缺口。
- 附录 A 溯源表的后段节号已相对当前参照系（§00–§19 共 20 节）系统性偏移约 3 节：P1 引「§13 勘误 K/L」而勘误在 §16；DP-2、DP-5 引「§15 五类对象」而对象总表在 §18；DP-4、§5.3 引「§14 推论」而推论在 §17；R4 引「§13 勘误 M」；非目标引「§16」而简化留白与边界在 §19。内容逐字对得上（勘误 K/L/M 确实存在且表述一致），但指针失效——把溯源表当「可追溯」证据展示之前必须全表复核。
- rank-topology-3d.md 的两个带宽数字（UB 196 GB/s 单向/卡、RoCE 400 Gbps/卡）在同仓 ub-reference 里找不到对应条目（那份手册给的是 400GE 单链路、2.1 μs 跨柜时延、16 PB/s 系统聚合），属于只有断言没有出处。另有一处可核对的偏差：文中写「48 node = 1 超节点 = 384 卡，摊在 16 个机柜」，而公开口径是 12 计算柜 + 4 总线柜，384 张卡实际摊在 12 个计算柜里（与缺省 nodeRack=4 自洽，与「16 个机柜」不自洽）。
- 全部材料零用户研究、零专家访谈、零基线对比，且参照系全文无一条外部参考文献。因此 P1–P4 目前是「设计者自陈的错误分类」，误判率只是被提议的指标而非已测数据；FR-7/FR-8 依赖的时间线还是合成数据（PRD R5 自己写明 M1 用合成数据验证视觉编码）。任何把 P1–P4 说成「已验证会导致用户误判」的措辞现在都超出了证据。

## 七个 pattern 实现盘点

**最强的原创点（按强度排序）**

- **把产品验收标准编译成页面内实时断言**（demo.html 的 accHTML）：A3/A4/A6/A7 是当场算出来的 pass/fail——A3 用 memParts(probe2) 与 memParts(probe8) 做 JSON 全等比较来证明「加 DP 不买余量」，A6 现场喂 heads=33/TP=16 检查校验是否拦截，A7 现场核对 PP×max(TP·CP, EP·ETP)。可视化论文里几乎没人这么干，这是最能立住的一条。
- **ZeRO 档位作为「非并行维」被显式建模，并因此让 A3 的极性翻转**：档位=0 时 DP=2 与 DP=8 的显存构成必须逐字节相等；档位>0 时必须不等且被切的那几档正好差 4 倍（8/2）。这是对 PRD 原命题「加 DP 不买余量」的一次真实修正与限定条件补全，不是复述——而且两面都当场断言，避免读者拨了档位看见 A3 变红以为自己调坏了配置。
- **图层可用性表按「渲染函数是否真的读它」收缩**（AVAIL + layerAvail）：dim/anatomy 只认 L5、chain 只认 L2/L3/L4、solid 的 L1–L4 只在 cav 子视角生效、story 五层全不生效。写在代码注释里的原则「按钮不能承诺一个渲染函数不会兑现的效果」是一条可以直接引用的界面诚实性准则。
- **SHARD 表：把「算子归哪一维」升级成「维 × 张量轴 × 份数 × 本 rank 持有区间」，并给出成表判据**——判据不是算子长什么样，而是它的权重/激活的哪根轴上有可分的份数。配套 createModel() 是无 DOM 的纯数据层，被 demo.html 直接当真数据源复用，这个数据层/渲染层分离是可主张的架构贡献。
- **逻辑魔方的布局不变量 + 可运行的几何回归**：「任一轴步距 ≥ 该轴卡块尺寸 + 最小缝 → 任何并行度组合下永不重叠」，配 verify-rubik-cube.mjs（2 配置 × 5 形态，每个折线顶点距卡心 ≤ 0.12，1500ms 内收敛）。它还自带一段可引用的失败史：「连线没连到卡上」复发三次，第三次正是「只断言端点」的检测盲区。
- **组合工作台的语义消息契约**：两格是同一 pattern 的两份 query 配置，格与格之间只走四条语义消息、不共享配置，并明确宣布「换 pattern 时要保住的是这几条语义，不是某一套 query 参数」。附带一条可引用的 URL 设计规则：台面替用户切的 tab 不写进链接，因为链接是「你发出去的那一屏」而不是台面顺手做过的动作。
- **URL 即状态做到了可交付的程度**（仅限 demo.html / rubik / net-sharding / combo-workbench）：43 个参数、只写偏离默认者、不认识的忽略、非法值静默退默认、旧链接别名硬性保留（v1..v5、memex）。这条支撑「审稿人点链接就能看到那一屏」的可复现性主张。
- **PP 那一屏的概念纪律**：拒绝把每一格画成单张 rank——每格是 pp_rank 相同的一整组卡锁步做同一件事，TP/DP/CP 折进格内，停在格上才展开完整门牌号 (pp,dp,cp,tp)。这是对 PRD P3/P4 两类结构性错误的正面回应。

**教科书内容 / 写进论文会被批的部分**

- **README 那张文字重叠对数表**——这是最该先处理的一条。机制（VW = clamp(692·AR, 1080, 2600)，AR<1.56 时钳在 1080，620px 下缩放 0.574，侧视标注固定屏幕字号）完全可核实；但 48/42/35、1/0/0、0/1/1 这九个数字没有脚本、没有原始数据、没有记录测法的提交（全仓是一次压缩初始提交，那条提交的信息还讲的是别的事），「重叠对数」本身未定义，且只报了宽度而没报高度——而 viewBox 恰恰是按长宽比反解的。现状写进论文必被要求出示数据。
- **「实测 3 次里 2 次」这类 n=3 的轶事**（combo-workbench 的回声竞态）以及 rubik pattern.json 里「已在 1 卡至 8192 卡、含退化与极端形状的配置上逐对验证」——后者与提交的脚本（只跑 2 个配置）直接对不上。这类未落成harness 的口头断言在评审里是负资产，要么补脚本要么删掉。
- **cube-cockpit.html**：376 KB / 5,221 行的体量却只有 ?theme 一个 URL 参数，无法用链接复现任何一屏；概念上已被 demo.html 与 combo-workbench 接管。写进 System 章只能表达「我们做了很多」，提不出可辩护的主张。建议压缩成两三句演进史。
- **pp-pipeline 的零 URL 参数**：内容本身（1F1B/GPipe 甘特 + 六个可调维 + 时间游标 + CP 分面）是合格的 V2 实现，但一条链接打不开「那一屏」。而且 1F1B/GPipe 甘特图本体是 GPipe 与 PipeDream 论文里的教科书图形，直接写会被指为复述——可主张的只有「不画单张 rank」那条纪律。
- **src/ 的 3D 机房建模**：README 自陈机柜内与板上布局是「基于公开材料的示意抽象，不代表真实工程布局」，且 URL 状态只有 hash 里的 mode。3D 数据中心可视化本身有大量既有工作，这部分写进去性价比最低。
- **「真实数据驱动」这个说法需要大幅收敛**。实际情况是三档，混在一起讲会被抓：① 真实公开数据但硬编码为常量（src/scene/data.ts，带 arXiv 溯源，可引用）；② 手工标注的真图（OPENPANGU_GRAPH 55 节点 + SHARD 表，是人写的、不是 trace 出来的，且**没有 shape**，所以所有字节仍由配置算出）；③ 确定性合成（rankLoad 的 sin-hash 负载抖动、arZoomSVG 的 AllReduce 进入时刻、路由不均系数）。**全仓零 profiling、零实测、零用户研究。**
- **data/ 下那两份 JSON 是死数据**：ascend-superpod-viz-spec.json 与 ascend-workload-pangu-moe.json 在源码里没有任何 import。若在论文里把它们列为「数据输入」会被 artifact 评审当场发现。
- **V5 没有独立成图**：PRD FR-9 明写「与 V1 并列，不嵌套」，实现却是 dim 视图的一个 cut 值（cut=cp，由 legacy 别名 v5 映射过去）。同理 A5/A8 在自检面板里标的是「交互/manual」而非实时断言。声称「五个视图族全部实现、A1–A8 全部通过」是不准确的，写的时候必须按 M1 完成定义（A1/A2/A4/A6/A7）来说，并把 V5 与 A5/A8 的状态如实标注。
- **投入与 PRD 正典的错配需要主动解释**：代码量最重的四屏（整网切分 ≈2,600 行、单维切分 ≈3,790 行、映射·交集腔 ≈2,900 行、五幕故事 ≈1,300 行）都是 PRD 里没有的视图；而对应 V1/V2/V4 的 renderV1/renderV2/renderV3 只有 220/70/210 行。这不一定是缺点（可能说明真正有用的视图是做出来才发现的），但必须自己先说，否则会被读成「按规范做的部分最薄」。
- **反爬与 noindex 对 artifact availability 的影响**：产品名以 base64 存在 src/content.ts、明文生成器被 .gitignore 排除、站点整体 noindex + robots.txt。投稿时的 artifact/availability statement 必须交代这一点，否则评审 clone 下来 grep 不到任何产品名会觉得有问题。
