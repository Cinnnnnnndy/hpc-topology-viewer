## 它是什么

一条下钻链 + 三张常驻悬浮卡 + 一块可缩放的画布。打开就是**集群**：4096 张卡物理上怎么连（灵衢的超节点 /
L2 平面 / L1 交换 / POD / 板上的 NPU·CPU·DPU·NIC），NPU 按 PP 段着色——并行拓扑已经叠在物理图上；往里
是**段**（一条 PP 段在模型里怎么分组）、**卡**（这张 rank 的层区间/显存/物理位置/通信组走哪一级）、
**单卡**（矩阵本体的 solo 渲染）。四层用同一套 chrome：顶栏面包屑、左卡、右卡、底卡一直在，只换内容。

默认预置 **moe504b32k**（`tp4·cp8·pp8·dp16·ep16`，world=4096）——参考训练工程 项目
`config/llm/moe_504B_A18B/` 里 32K 序列那档的真实切分（504B 总参/18B 激活）。`dp=16` 不是猜的：项目代码里
`data_parallel_size = world_size ÷ (TP×PP×CP)`，EP 落在 DP 域内、必须整除 DP，`DP=EP=16` 是这组切分的最小
合法值。默认预置先后改过三次（pangu → moe718b128k → dense64 → moe504b32k），每次的原话与取舍见 `pattern.js`
「默认预置」那段注释；四档旧预置都没删，`?preset=` 照样认得。

## 故事线：集群 → 板 → 卡 → 单卡

反馈「按下钻的逻辑把整个视图串起来，而不是视图 tab 切换」。不再有并列的画法切换，画布停在哪一层由
下钻状态决定：

1. **集群**（默认第一屏）——灵衢物理拓扑，内联 SVG。滚轮以指针为中心缩放、拖拽平移；点一个 POD 或
   超节点取景过去，点空白复位。点一颗 NPU = 选中 rank（进「卡」）。
1′. **板**——POD 取景之后再点它里面的一行，或右卡「→ 板 N」：画布换成这块板的 Server 形态图（下一节的
   表里「板」那一行的全部关系，一处不落）。板上点 NPU = 选中 rank；面包屑 `集群 › 板 158 › rank 1267`。
2. ~~段~~——**已撤下并归档**（反馈「这个视图先不做，归档到另一个分支，起个名字放启动页」）：宇宙视图 / 径向星图
   整份代码在归档分支（旧链接复原时一并从启动页与发布工作流撤下，代码仍在该分支）。本页左卡的 PP 段按钮现在是**原地聚焦**那一段
   （其余段压暗，再点取消），不换画布。
3. **卡**——任一层选中之后右卡先摆坐标行（不留空白），紧接着借矩阵本体一次不铺屏的 `?brief=1&sel=`
   请求（`ptoRankBrief()`，跟第四层读的是同一份口径）把层区间/显存构成算回来，原地升级；再加物理位置
   与五个通信组各走哪一级链路。
4. **单卡**——「↓ 单卡下钻」换到矩阵本体（`fastcard=1&solo=1`）：真实容量读出、显存构成（原色）、卡内那一级
   通信。矩阵里点空白退出 solo，`pto:tier` 报回来，这一层退到上一层，不重新加载。

标题即面包屑，放在左上角：`MoE 504B(A18B)·32K序列 / rank 1271 / 单卡` 或 `… / 板 158 / rank 1267 / 单卡`，
每一级都能点回去（回板层保留选中、点模型名回集群并复位画布）。原来顶部居中的那条面包屑、单卡页自己左上角的题面
（demo.html opt-in `notitle=1`）都并进这一处，页面上只有一个标题。

  两条线的值。
- **设备各有各的形**：只有 NPU 是实心格（填充 = 占用率这份数据），CPU 是空心方框、DPU 是空心菱形、NIC 是四根端口短竖线，
  交换机是轮廓。放大到 3× 出列头（CPU / NPU · POD n / DPU / NIC）和板分隔线，6× 出每格的 rank 号。

  `icon-defs.js`的 2D 图标——NPU 昇腾封装、CPU 鲲鹏、NIC 擎天、UB 交换机——按深色默认态逐元素转成
  `<symbol>`，本页用 `<use href="#hw-*">` 引用：集群层的 CPU / DPU / NIC / L1 / SW2、放大到 6× 时每格 NPU 的封装、板视图

  checkout 里用一个假的 `createElement` 跑 `HWICONS.build(id, null, R, false)`，把结果包成 `<symbol viewBox="0 0 48 36">`。

  不用渐变、玻璃、发光、阴影。rank 是正方形宫格（每板一行 8 格，POD 8×8）。
- **选中**：白色边框套在格子外、中间留一圈底色缝，格子本身的灰度不动；左上侧一条短细引线 + 一行
  「rank N · 67.5 GB」，只给当前选中那一格。
- **PP 段柱状选择器**（左列）：每段一根柱、共用基线，柱高 = 段内占用率最高那张卡，灰度同画布，虚线是 100%；
  只有选中那根柱顶上写数值，点柱进段。
- 画布铺满整个视口，四周是悬浮的毛玻璃小卡（半透明 + 模糊，画布透得过来）：左列拆成标题 / PP 段柱 / 容量告警三张，
  故障问题每条一张，右侧 rank 读数、面包屑、工具条同一种玻璃。取景把内容摆进卡与卡之间的安全区正中。

**ZeRO 档位**（反馈「红色这么多，一下告警会有这么多红色么？」）：矩阵本体的显存估算默认不切优化器（ZeRO-0），
每卡存一整份 fp32 优化器态（约 46 GB），默认预置 4096 张里 3959 张顶出 64 GB。这不是这套配置真实会报的告警：
Megatron 系训练大 MoE 常规开分布式优化器（等价 ZeRO-1，优化器态沿 DP 切 16 份），开了之后全部卡在 32–42%。
所以 moe504b32k 在本页默认 `zero=1`（**假设**——504B 那份 yaml 不在本仓库，没逐字核对 `use_distributed_optimizer`），
第一屏是暗灰，红色只留给真告警。左列图例下有 `zero 0 1 2 3` 一排小按钮，切到 0 就能看到「不开会爆显存」的对比；
档位写进 URL（`?zero=0`），传给矩阵的三种请求（集群聚合、选中卡读数、单卡层）都带上。

| zero | 超容 | 逼近红线 | 占用率中位 / 最高 |
|---|---|---|---|
| 0 | 3959 | 137 | 103% / 113% |
| 1（默认） | 0 | 0 | 35% / 42% |
| 2 | 0 | 0 | 24% / 30% |
| 3 | 0 | 0 | 16% / 23% |

**落位是假设**：配置里没有 rank→NPU 的映射，这一层按「rank 连续摆放」推（`r → 超节点 ⌊r/1024⌋ · POD ⌊r/64⌋ ·
板 ⌊r/8⌋ · 槽 r%8`），左卡与右卡都写明。在这条假设下能算出真东西——五个通信组的成员由矩阵本体的
`rankOf = ((pp·DP+dp)·CP+cp)·TP+tp` 反算，组内最远的一对落在同一块板 / 同一个 POD / 同一个超节点 / 跨超节点，
就是它走的那一级：默认预置里 TP（4 卡）在板内 fullmesh，CP（×8，跨 8 块板）与 EP（16 张连号，与矩阵同一口径）在 POD 内走 L1，
DP（16 个副本）跨 POD 走 L2 平面，PP 相邻段跨超节点走 UBoE。选中一张卡，它的五个组成员保持原灰度、其余压暗，组别按维度色描边
（与矩阵本体同一套色，见「每一屏的关键要素上色」）；
EP 与 DP 成员完全一样时（DP=EP）合成一行，不摆两行一样的话。

## 真实故障复盘（两条链）

反馈「这些数值卡片就是应该直接出现在进去的第 1 个视图中」「不要靠 tab 切换看数值，空值横杠不要显示」
「不要堆砌在最下方，以悬浮卡片分布在画布四周，最好有一个链路式」「先只出现问题，点击问题再出现相关的

## 两套 rank 编号

逻辑魔方与并行拓扑矩阵各自独立实现了一遍「rank ↔ (tp, cp, pp, dp) 坐标」的换算，内部打包顺序不一样：

| | 打包公式 |
|---|---|
| 逻辑魔方 `pattern.js` | `rank = ((rep × PP + pp) × CP + cp) × TP + tp` |
| 并行拓扑 `demo.html` | `rank = ((pp × DP + dp) × CP + cp) × TP + tp` |

同一个数字在两个系统里指的不是同一张卡，必须按坐标四元组换算（`rubikSelToMatrixSel()`）。这一层的物理
画法与宇宙视图都直接用矩阵本体的编号，只有逻辑魔方抽屉报上来的选中要换算。已验证：pangu 预置逻辑魔方
rank 830（`tp6·pp3·rep20`）→ 矩阵 rank 2566，矩阵读出 `tp6·cp0·dp20·pp3`；moe718b128k（CP=16）逻辑魔方
`tp3·cp9·pp8·rep2` → 矩阵 rank 4427，读出 `tp3·cp9·dp2·pp8`，逐位一致。

## 同一套系统：切分只有一个来源

反馈「全篇所有的状况要和集群数目、切分数目对得上，是同一套系统；之后改各个切分的数值，整体要一起改」。

- **一个来源**：预置给默认值，URL 的 `tp / cp / pp / dp / ep` 覆盖（设置「并行配置」里 ×2 / ÷2 调好点「应用」，写进 URL
  重载）；`world = tp×cp×pp×dp`。物理图、层级剖面、泳道、通信组、数据卡都读这一份；矩阵本体（借来算数的 brief、单卡层）、
  整网图、逻辑魔方的链接一律显式带上同一组数（`splitParams()` / `rubikParams`），不再各自按预置名去查自己那份表。
- **物理链一起带**：矩阵默认按 CloudMatrix384（超节点 384 卡）判跨不跨超节点，本页画的是 Ascend 950 1024P，所以一并传
  `perNode=8 / nodeRack=8 / podCards=1024`，两边对同一条边给同一个载体答案。
- **运行时核对**：矩阵报回它实际按哪组切分算的（`brief.config`），本页逐项比对，对不上左列挂「与矩阵 不一致」；切分改得
  不合法（如 heads % TP ≠ 0）时矩阵报 `ok:false` + 原因与建议，左列与设置里当场说清楚。
- **这次查出并改掉的两处不一致**：① EP 组本页原来按「DP 维每 EP 个副本一桶」算，矩阵按「(dp,cp,tp) 拉平后连号 EP 个」
  （Megatron 的 tp-ep-dp 排法）——默认预置里同一个 EP×16 组，本页说走 SP、矩阵说在 POD 内；现在本页照矩阵的口径
  （`epMembers`），右卡 / 层级剖面 / 并行对象高亮一起改。② 物理链的超节点大小（384 vs 1024），见上。
- 逻辑魔方（别的 pattern）自己的模型要求 EP 整除 DP；切分改到它画不了的组合时，魔方面板直说，不加载。

## 单卡层：显存 / 整网分片 / 层构成

单卡放大到满屏之后，卡里的各档显存（权重 / 梯度 / 优化器态 / 激活 / 碎片）画成**一块块独立的板**：

  激活按在途微批。占比不到 0.5% 的块（router、norm）不单画，最窄的块给 3.5% 宽——精确数字在左侧逐块列着。

- 底栏在单卡层多三颗切换（`?rv3=` 记在 URL 里，切换不重载）：
  - **显存**：上面这套显存板。

    按刀色淡显，块里只有它拿走的那一片（TP 第 t 片 / EP 第 e 桶）实心——PP 切层、TP/EP 切宽度，一眼看出它拿走的是哪一块。
  - **层构成**：只画这张卡自己的层，逐层一排它实际拿到的算子块（字节 = 每卡字节，颜色 = 切它的刀），块间、层间都留缝；
    首段 / 末段多一行 embed / lm_head。
- 切分组不挂文字牌（TP0 / CP0 / DP3 / PP7 / EP 组）：组与组之间靠间距分开（TP 行距、PP 段缝、EP 组缝，
  CP 块之间再掰开一条更宽的缝——层级越高缝越宽），展开的兄弟 rank 棱色 = 它与选中卡同组的那一维（TP 青 / CP 绿 /
  EP 紫 / DP 蓝 / PP 橙），不再整体去色。
- 兄弟 rank 画成实心块（只画朝向读者的三面，同色细边，不再是 12 条棱的线框），整体淡显、不与选中卡和连线抢；展开时按与选中卡同组的那一维轻染色，

- 通信连线（底栏「通信」）在单卡层把五维都连上：原来 TP/CP/DP/EP 交给全景里的地面流量带画，单卡层没有那层，

  线的两端落在看得见的块上。全景那层地面流量带在单卡层不再叠画。

## 层级串联动效

每一次换层都是同一种「推近 / 拉远」的语言，进出走同一条路径：

| 换层 | 动效 |
|---|---|
| 取景 POD / 复位 | 镜头 ~480ms 缓入缓出飞过去（缩放按对数、中心按线性插值），不再一帧跳 |
| 集群 → 板 | 先把看不见的板视图摆好、量出它那 8 颗 NPU 的屏幕位置；集群镜头把这块板的 8 格正好飞到那里，再淡入板视图（格子原地换成 NPU，无尺度跳变）；板视图从 NPU 那一排开始，按离它的竖直距离由近到远搭起来 |
| 板 / 集群 → 单卡 | 当前画布朝选中那一格推近；单卡页淡入时只有玻璃壳，淡入走完显存板自下而上逐档码上去（整网分片 / 层构成按行） |
| 单卡里换兄弟 / 换内容 | 新卡的板同样逐档码上去 |
| 展开兄弟 rank | 由近及远涟漪：TP → CP / EP → DP → PP |
| 打开通信 | 连线淡入 |
| 返回 | 推近的镜头拉回下钻前的取景；从板回集群，集群图停在对齐那一排、再一路拉远 |
| 卡片 / 标题 | 上下文换了（层 / 档 / 选中）时各列卡片错峰淡入上浮；同一上下文里的重画不播。面包屑新出现的一段从左边滑入 |

实现上只在一处记「之前」：`trail`（进板 / 下钻前那一层的镜头），回到同一层用一次就丢，换了层或点标题复位就作废，
不跨状态引用旧镜头；推近飞行时 SVG 临时提成合成层（拉远不提，否则光栅比例钉在高倍）；飞行途中细节档取起止两端较低的
那一档、不中途切；读者滚轮 / 拖动随时接手；预载的单卡页只在第二档以 1% 预热，其余时候完全透明，不留旧卡的影子。
系统开了「减少动态效果」时全部直接落到终态。单卡页里的编排是 demo.html 的 opt-in 消息（`pto:solo` 的 `play:'stack'`、
兄弟 / 通信从关到开），独立打开时不变。

## 数据卡（训练 / 推理要看什么，按层出，逐类可关）

反馈「训练推理过程中需要哪些数据、不同大小（下钻层级）要看到哪些数据，做成悬浮小卡飘在四周，能通过设置打开/关闭
某种类型——非常重要，做细致的调研」+「把并行拓扑里点开 rank 那张卡拆开，每个小切分和对应数值做成单独的卡，放在
单卡视图四周」。调研来源：`research/` 的学习笔记（训练监控设计文档的模式 A/B 指标、昇腾监控 ingest 数据源清单、
算子并行框架融合改进方案 §9 的异常形状→根因、§12 推理 H²P 的时间切片语义）、并行拓扑 `demo.html` 的配置面板
（数据标注五键、通信粒度、观察层级）与整网图逐算子读数、`src/scene/data.ts` 的 `STEP_DECOMP` / `WORKLOAD`。

九类，设置浮层「数据卡」逐类开关（`?dhide=`），工况 训练 / 推理（`?mode=infer`）：

| 键 | 名称 | 内容 | 口径 |
|---|---|---|---|
| `cap` | 容量 | 集群：四档分布 + 最满那张；POD：峰值/均值/超容张数；板：八卡逐张占用条 | 实算（`ptoClusterBrief`） |
| `state` | 显存各档 | 单卡层：权重 / 梯度 / 优化器态 / AllGather 窗口 / 激活 / 优化器步临时区 / 碎片，每档一张，带归属与相位、ZeRO 切几份 | 实算（`ptoRankBrief().detail`，与矩阵读出卡同一批函数） |
| `wshard` | 权重切分 | 单卡层：权重带里逐块一张——哪个算子块、被哪把刀切（TP/EP/复制）、怎么切、多少 GB | 实算（`wCutBlocks`） |
| `comm` | 通信 | 集群：各维在哪一级闭合 + TP/PP/DP 每条边字节 + 载体带宽；POD：本级闭合；rank / 单卡：各维每边载荷（CP/EP 不给数） | 实算（`commLoad9`）+ 落位假设 |
| `pipe` | 流水·气泡 | (PP−1)/GA、每段层数、μbatch；rank 的层区间与 ZeRO 档 | 实算 |
| `phys` | 物理 | 板：H2D / NIC / fullmesh / 出板 / NIC 交换的配对 | 假设（连续落位）+ 直播四页 |
| `step` | 步时 | 训练：计算/通信/访存占比 | 示意（盘古 Pro MoE 报告，800I A2，非本硬件） |
| `infer` | 推理 | 推理工况：prefill / decode 吞吐、TTFT / TPOT、batch、MTP，prefill / decode 各自的步时分解 | 示意（同上；KV cache 未建模） |
| `inc` | 故障复盘 | 左列两条故障链 | 复盘（另一次训练的原文） |

板 = 八卡占用 · 板载配对；选中 rank = 右卡（显存 / 位置 / 通信组）+ 通信载荷 · 流水；单卡 = 并行拓扑那张 rank 读出卡**拆成小卡，排在
左列、接在配置卡下面往下排**：先模型态（权重 → 逐块切分缩进一级、梯度、优化器态），再执行态（激活、碎片…）；每张可点开，
内容就是并行拓扑读出卡里点开那一块时的那一栏（`memBlockDetail` 原文拆成结构：dt/dd 行、腔图、对应通信、兄弟卡）。右列：
rank 位置与通信组、各维通信载荷、流水。

**消融**（反馈「字太多、只留 key 和 value、不要解释的词语，所有部分做消融，一定要简洁」）：卡面只有名字与数值；
归属/相位、怎么算、为什么——一律收进悬停。口径小标只标例外：默认就是实算，只有「假设」「示意」才挂标。单卡切分小卡
收起时一行（名字 · 切法 · GB），点开后也只有 key/value（每层形状、参数量、层段、切法、通信「维 原语」）+ 一张腔图，

## 连线样式

照 「硬件图元库 · 连线样式」的结构去色：每条稀疏干线 = 底色衬边 + 芯线，芯线的实/虚节奏区分介质
（铜缆实线、光 UB 虚线 7 5、UBoE 稀虚线 4 7 半透明、RoCE 3 3 + 端头空心环、PCIe 点线）；两端是一颗比线略粗的实心小点
（marker，颜色跟线，随线宽缩放），并进总线的一头是再淡一档的汇接点。太细时换显示方式：集群总览线宽不到 1px，不画衬边、RoCE 收成
实线压淡；成束的密线（出板 Clos 64 根、fullmesh 28 根）平时只是发丝线，只有选中那颗 NPU 的那几根换成白色激活样式。

**直角走线（10.10）**：反馈「连线凌乱」「又有直线又有弧线」。板视图所有连线统一成横平竖直、转角 5 的小圆角，不再混用弧线和斜线：
- 板内 fullmesh 28 根：原来是 NPU 行上方叠成扇形的弧；现在分 7 层轨道，跨距 d 的那一对走第 d 层（NPU 顶边上去、横过去、下来），
  7 层叠起来是一组平行轨道。选中一颗 NPU 时它那 7 根成一组阶梯，TP 组员那几根仍是青色。
- 出板 Clos 64 根：原来 64 根斜线交叉成网；现在是 8 条平面轨道（平面 k 走第 k 条），每颗 NPU 往下穿过全部轨道，每颗 L1 只从自己那条落下，
  也就是交叉开关（crossbar）的画法。
- H2D / NIC→NPU：CPU、NIC 往下到各自的分叉轨道再落到 NPU；NPU 顶边分三个口——H2D 在左、fullmesh 居中、NIC 在右，互不共线。
- L1→本平面 4×SW2、L1→交换板、CPU↔CPU、PCIe、UB、NIC 交换：一律改成同样的直角圆角走线。
- 共线的几根线叠在一条轨道上，半透明会越叠越亮，所以改成实色分档：平时暗灰，选中那颗 NPU 的线白色、画在最上层，其余再退暗一档。
- 各层走线的名字（fullmesh / Clos / 框间）收到左侧留白里右对齐，不压在线上；NPU 行下移 24，给上方轨道让位。

**线收细、拉开层级（10.10.1）**：反馈「太粗了，看不到重点」。器件是主角、线是背景：平时密线（fullmesh / Clos / 交换板）收到 .6、
H2D / NIC / L1→L2 .7、干线 .8–1，衬边从 4.5 收到 3。选中一颗 NPU 时整张板进聚焦档：它自己的线是唯一亮的（白 1.1，TP 组员那几根青 1.3），
其余密线退到几乎看不见，RoCE / UB / PCIe / NIC 交换这些干线退成暗灰、端点小点收掉、层名压暗。

**层距收紧、再收细（10.10.2）**：反馈「缩小层叠线之间的间距」「粗细再收一下」。fullmesh 7 层与 Clos 8 条轨道的层距都从 6 / 8 收到 4，
Clos 那组轨道整组落在 NPU 行与 L1 行正中，NPU 行回收 12。线宽再降一档：密线 .45、H2D / NIC / L1→L2 .5、干线 .6–.7、衬边 2.2；
选中那颗 NPU 的线 .8（TP 青 .9），重点靠亮度而不是粗细。

**线束 + 黑色描边（10.11，参考 BMC 仓库 bus-wiring 的连线）**：反馈「线束之间的间距还要再收」「线旁边做黑色描边防止遮挡」。
BMC 那套走线的要点是**每根线一条自己的车道、平行不合并**（`computeRoute` 的 `parallelGap`，线心间距约 1.8× 线宽）。照此：
- NPU 顶边出 fullmesh 7 根一束、底边出 Clos 8 根一束，束内间距 2.2；Clos 的 8 条平面轨道间距同为 2.2，整组落在 NPU 行与 L1 行正中。
- fullmesh 每一对单独占一层：按跨距从短到长依次放进最低一层、且不与这层已有横段相叠——短的在里、长的在外，不再有两根线共用一段。
- H2D / NIC 的入口挪到束外两侧（−12 / +12）。
- 所有密线（fullmesh、Clos、H2D、NIC、L1→L2、L1→交换板）也垫一圈底色描边（1.5，选中时 1.3），交叉处被切开、看得出谁压谁；
  选中那颗 NPU 的线连同它的描边一起挪到最上层。

**束内收齐（10.11.1）**：反馈「NPU 那块为什么没有收束，间距不一致」。
- NPU 顶边原来是 fullmesh 7 道（间距 2.2）加两侧离得远的 H2D / NIC（±12），现在 H2D、NIC 并进同一束的最左、最右两道，顶边 9 道等距。
- 束里的车道按**套环顺序**排：近的伙伴在外道、远的在里道（fullmesh 往左拐的从最左道起依次 i−1 … 0，往右拐的从最右道起依次 i+1 … 7；
  Clos 往左拐的按平面升序在左、往右拐的按平面降序在右、本平面那道居中直落 L1）。外道拐得早、里道拐得晚，同一束里的线拐出去不再互相横穿。
- 离开 NPU 先直走一截再分叉（束的「颈」）；底色描边不再带 data-n，选中时不会被当成链路标亮。

**线束方案推到全局 + 虚线改实线（10.12）**：反馈「按现在的方案全局调整」「虚线效果非常差，全部调整」「连线遮挡、间距不一致」。
- **通用车道规则**（`laneMap`，板视图与集群共用）：一束线里往左拐的排左、往右拐的排右，**先拐的在外道**，拐出去不横穿同束的线。
  H2D、NIC 这类从远处来、最后才拐的线自动落在束的**正中间**——两侧往外拐的 fullmesh 碰不到它们（原来在束最外侧，被 fullmesh 横穿）。
- **板视图剩下的共用段全部拆开**：CPU 底边一束（CPU0 = PCIe · UB · H2D×4，CPU1 = H2D×4 · UB）、DPU 底边两道；DPU 与 CPU0 的 UB 各走各的进 P1；
  NIC 底边两道；进 NIC 交换的 6 根各走一条轨道、在 SW 顶边各占一道；L1 底边一束 6 道（4×SW2 + 交换板 A / B），去交换板的 16 根各走一条轨道、
  交换板顶边 8 道。行距随之下移（NPU 行 194、交换板 418、L2 484）。
- **选中时 fullmesh 等距**：全局排层时一颗 NPU 的 7 根散在不同层、间隔忽大忽小；选中就把它们抬到所有背景层之上、按距离一层一层排（近的在下），
  层距同束内间距，取消选中还原（`liftMesh`）。
- **集群放大后原地展开的那块板**：弧线、斜线全部换成同一套直角线束——上方 Clos 与 CPU / DPU 的 UB 每颗器件一束，拐进 L1 下方 8 条平面轨道；
  下方 fullmesh（`meshPlan` 同板视图）→ H2D → NIC → NIC 交换 → PCIe 分层；L1 → SW2 各走一条轨道。束内间距与轨道层距统一 0.5。
  板行之间只有 2 格缝，线只能从别的行身上过，所以展开关系时这个 POD 的其余行**让位**（盖一层与 POD 同色的底，当前行挖空），
  线画在干净的底上、画在器件之上，不遮挡也不被遮挡；移开或取消选中恢复。
- **集群总览 L1 → L2 平面**：64 根斜线改成每颗 L1 往上到本组上方的轨道、横到两列组中间的走线槽、槽里每根一条车道往上、到平面下方再各走一条轨道落上去。
- **虚线全部改实线**：细线上的虚线节奏只剩噪点、缩放时段长还跟着变。介质改用灰度区分：UBoE 最亮 → PCIe → UB → RoCE 最暗；
  集群行框、流水线图与泳道的辅助标记同样实线；单卡 / 整网图引擎里的虚线也统一关成实线（原来靠虚线区分的虚影本身就带压低的透明度或另一种颜色）。

**虚影 / 备选仍用虚线，统一线型（10.12.1）**：反馈「虚影和备选还是用虚线，只是调一下虚线的线型」。连线的介质区分仍是实线 + 灰度；
单卡 / 整网图引擎里表示虚影、备选的虚线恢复，但原来各处各写一套节奏（5 4、3 3、2 3、9 5、1.5 1.5 …），现在统一按**自己的线宽**取同一比例：
实段 3.5×线宽、空段 2.5×线宽、平头（线宽已按缩放折算，任何倍数下疏密一致）。表示通信方向的流动层（dashoffset 动画）不动。

**连线上的数据（10.13）**：反馈「在必要的连线上显示之前讨论的数据，不要明显的大标签；放大一定程度时显示小标签，需要注意的数据高亮；不影响整体视觉和排布」。

**2.5D 用 Node 的立体元素（10.24）**

反馈「现在的 2.5D 用的是 Node 里面的立体元素吗？看不出来」：10.23 只是把平面图斜过去、底板垫一层板厚，器件仍是平的。10.24 把集群 2.5D 按 硬件图元库（`src/scene/scenes.tsx`）的立体语汇重画。这是 SVG 里的同语汇重画，不是把 Node 的 three.js 组件或 GLB 模型嵌进来，因为 4096 卡的集群图要保持一张 SVG 才能平移 / 缩放 / 联动选中。

| 本图 | Node 里的元素 | 块高（屏幕 svg 单位） |
|---|---|---|
| SuperPoD | 基板 `Slab` | 0 → 3 |
| L2 平面 / L1 SW | 交换柜 `CabinetBox` | 3 → 8 / 3 → 5.5 |
| POD | 托盘 | 3 → 4.4 |
| Board | 刀片 `BladeTray` | 4.4 → 5.2 |
| NPU | 芯片块 `NpuChip` | 5.2 → 7.6 |
| CPU / DPU / NIC | 小芯片 `CpuChip` | 5.2 → 6.2 |

- 每块 = 顶面 + 朝向读者的两个侧面：左前面迎光（亮一档）、右前面背光（暗一档）。侧面按最终轴测投影烘焙成多边形，同类同一行并成两条 path（`.p-ex`），只在 2.5D 落定后淡入。顶面由 CSS 按层高抬起（`--z-*`，写在 svg 上）。

- 平面模式不受影响：侧面隐藏，顶面不抬。

**2.5D 阶梯 + 细化模型（10.25）**

反馈「减少 rank 的高度做出阶梯的形式，然后细化所有的模型」。

阶梯：每一层只比上一层高一级台阶，越往里台阶越矮，读起来是一级级往上收的梯田。10.24 里 NPU 一块就高 2.4，比刀片和托盘加起来还高，整片看像楼群。

| 层 | 顶面高度（屏幕单位） | 这一级台阶 |
|---|---|---|
| SuperPoD 基板 | 2.2 | 2.2 |
| POD 托盘 | 3.4 | +1.2 |
| Board 刀片 | 4.2 | +0.8 |
| CPU / DPU / NIC | 4.8 | +0.6 |
| NPU（rank） | 4.9 | +0.7（原来 +2.4） |
| L1 SW / L2 平面交换柜 | 4.6 / 6.2 | 仍是最高的「立柜」 |

细化模型，照 Node `scenes.tsx` 里各部件的构成：
- **棱线**：照 Node `Slab` 的 `<Edges>`（rackEdge `#3D4452`），画顶面四边加朝向读者的那根竖棱，只给基板、交换柜、POD 托盘这几百个大件。刀片顶面本来就有描边，器件和 NPU 放大后有立起来的部件。试过给这几千个小件也各描一圈，结果全景糊成一层灰，放大后每帧重绘也慢了约四分之一，选中时镜头飞行会卡，所以去掉了。2.5D 下顶面圆角收小，和直角侧面对得上。
- **交换柜（CabinetBox）**：前脸一扇内缩柜门（rackDoor）加三道通风格栅（vent）。
- **NPU（NpuChip）**：放大到 3× 起，顶视图标换成立起来的部件：封装顶面（npuBody）上一圈内缩基板，后排 2 颗计算 Die，中间一道 UMA 桥，前排 2 颗 IO Die。占用条留在封装前沿，因为那是数据。Die 组跟在每颗卡的占用条后面，压暗和选中都跟着那颗卡走。
- **CPU（CpuChip）**：封装加内缩金属顶盖。**DPU**：卡体加中间主芯片。**NIC**：卡体加侧边光口笼。同样放大到 3× 起替换顶视图标，按 POD 第一次进画面时补建，每个 POD 并成几条 path。
- **配色**：只取 Node dark 调色板里的中性色（npuBody / npuTop / cpuBody / metal / rackDoor / vent）。Node 里青色、橙色的发光条没搬过来，因为这张图里色相只留给通信组和告警。
- **平面模式**：不受影响，仍是顶视图标。

**除高亮外一律黑白灰（10.26）**

反馈「现在有些隐隐的蓝色，我要求全部除了高亮的彩色都是黑白灰的」。蓝调有两个来源：
- **2.5D**：10.24 / 10.25 用的 Node dark 调色板本身是蓝灰，例如 npuBody `#2B303A`、rackEdge `#3D4452`，IO Die、DPU 主芯片更偏蓝。
- **界面**：沿用的苹果系中性色带一点蓝，例如 `#F2F2F7`、标签色 `rgba(235,235,245,.6)`、`#1C1C1E`、`#6A6A6E`。

处理：`pattern.css` / `pattern.js` 里所有低彩度（R/G/B 最大差 ≤ 45）的颜色，一律换成同明度（Rec.709 亮度）的纯灰，R = G = B，共 60 多个色值。明暗层次不变，只去掉色相。

保留的彩色只有高亮：五个通信组签名色（TP / CP / EP / DP / PP）、告警红、阈值琥珀、选中黄，以及 NPU 页显存构成的类别色（10.13 起按反馈保留）。

核对方法：逐屏截图扫「偏蓝的灰」像素（彩度 4–40 且蓝分量最大）。10.25 的 POD 放大图约 26 万点，现在集群平面 / 2.5D、POD、选中、四个抽屉都是 0。NPU 页只剩彩色数据块抗锯齿边缘的几十个点。

**集群 2.5D / 3D = 硬件图元库 的立体图元（10.27）**

反馈有三条：
- 「用我做的一系列 node 里的节点」；
- 「之前的 2D 用的是这个仓库里的版本吗？要两个保持一致」；
- 「确保替换之后可以流畅运行到万卡的级别」。

**同一个图元库、同一个提交**：
- **2D**：`hw-icons.js` 来自 `icon-defs.js`。
- **2.5D / 3D**：`engine/hw3d` 用 `entity-builders.js`，与 `icon-defs.js` 是同一批 13 个图元的立体版。
- **颜色**：两边都照搬图元库原色。2D 撤掉了早先的去色相和提亮；立体用库的深色态 `_CD`，状态混色同库的 `_applyStatus`。
- **渲染一致**：helpers（Phong + 描边 + 圆角盒）照抄库页面的 `_makeHelpers`，three.js 用库自带的同一份 r134，光照和颜色与库页面一致。
- **DPU**：库里没有 DPU 图元，两边同一个补法：nic 卡加一颗大 ASIC。
- 以上文件原样放在 `vendor/hw-elements/`。

**立体不另排版。** 宿主把平面图里每个对象的矩形原样发给引擎（`hw:layout`），包括 SuperPoD、L2 平面、SW2、L1 SW、POD、Board、CPU、DPU、NIC、NPU。引擎把对应图元原位立起来，平面 (x, y) → 世界 (x, 0, y)，器件按库里的比例等比缩进自己的格子（同 2D `<use>` 的 meet）。2D 与立体是同一张图的两种画法。

| 平面图里 | 立体 |
|---|---|
| NPU 格 | `npu` 图元；状态位 = 平面图同一档占用灰；超容 = 库的「繁忙」状态（整件混红） |
| CPU / NIC / L1·L2 交换 | `cpu` / `nic` / `ub_switch` |
| DPU | `nic` + 大 ASIC |
| Board 行 | 库 `blade` 的托盘语言：MAIN 托盘 + METAL 前面板 + 黄铜包边 + 状态灯条 |
| POD / L2 平面 / SuperPoD | DARK 托盘 / DARK 柜体 / 库画布色 `#313232` 底板 |

**工具条集群段：平面 | 2.5D | 3D。**
- 2.5D：正交轴测，镜头方向 [1, .82, 1]，只平移、缩放。
- 3D：透视，左键转、右键或 Shift 平移。
- 两种模式都是滚轮以指针为中心缩放。

**联动。** 层级、面包屑、卡片仍归宿主管：
- 每次选中、层级或告警变化，宿主把平面图上每颗 NPU 此刻的 class 编成一个字节发过去（`hw:set`）：选中 / 组员 / 压暗 / 占用档 / 超容。两边永远是同一个状态。
- 引擎里的点选回传成平面图里的同一次点选（`hw:pick`）：点格子选 rank，再点放大到 POD，POD 已取景时点板进板，点空白先取消选中、再退出。
- 取景同平面图，把内容摆进卡与卡之间的安全区正中。

**万卡性能。** 做法：
- 远看每个器件是一块实例化方块，顶面颜色同平面图那一档。
- 容器同类尺寸一致，各烘一个模板做实例化。
- 镜头进到 POD 尺度，画面附近最多 12 个 POD 换成完整图元（烘焙模板实例化），并补上托盘和刀片的描边。器件自己的细线（鳍片、端口格）不画。
- 按需渲染：静止时不画。

| 卡数 | 远看 | 放大到 POD | 宿主每次同步 |
|---|---|---|---|
| 4096 | 11 次绘制 / 24 万面 | 23 次 / ≈78 万面 | 2.4 ms |
| 10240 | 11 次 / 35 万面 | 23 次 / ≈90–130 万面 | 5.6 ms |

被替换掉的：10.23–10.25 用 SVG 自画的轴测投影、侧面烘焙、阶梯层高（`g.iso-g` / `.p-ex` / `.p-npu3d` / `.p-d3`）。SVG 轴测投影的代码还在但不启用，其余已删除；`?view=iso` 现在打开的是新引擎。

**不暴露仓库（10.28）**

## URL 参数

| 参数 | 取值 | 作用 |
|---|---|---|
| `preset` | `moe504b32k`（默认，`tp4·cp8·pp8·dp16·ep16`，world=4096）\| `pangu`（`tp8·pp5·dp100·ep2`，4000）\| `moe718b128k`（`tp8·cp16·pp16·dp4·ep4`，8192）\| `incident2048`（`tp1·pp4·dp512·ep64`，2048）\| `dense64`（`tp4·pp4·dp4·ep1`，64） | `dense64` 是唯一一条 `world ≤ 64` 的预置：直接铺满矩阵本体原页，没有这套下钻链 |
| `sel` | 矩阵本体的 rank 编号 | 打开直接进「单卡」层 |
| `dhide` | `cap,state,wshard,comm,pipe,phys,step,infer,inc` 的子集 | 关掉哪几类数据卡 |
| `mode` | `infer` | 工况切到推理（缺省训练），集群层的步时卡换成推理指标卡 |
| `hide` | `occ,num,rel,grp` 的子集 | 关掉哪几类数据标注 |
| `obj` | `tp|cp|ep|dp|pp:下标` | 并行对象高亮 |
| `cam` | `top` | 单卡页用顶视（缺省 3D） |
| `comm3` | `1` | 单卡页画通信连线 |
| `zero` | `0`–`3` | 优化器切分档位，传给矩阵的显存估算；moe504b32k 默认 1（假设），其余预置默认 0 |

## 它不回答什么

- **并行度组合切换**——两个本体各自的 preset / 自定义 tp·cp·pp·dp·ep 都还在，这一份把默认值定死在
  moe504b32k，换配置用 `?preset=`。
- **真实的 rank→NPU 落位**——那是调度/启动脚本的事，配置里没有；这里只按连续摆放假设，并且写在脸上。
- **矩阵本体之外的第二套显存/容量算法**——所有数字都借矩阵本体算（`?brief=1`），这一层只摆版式。
